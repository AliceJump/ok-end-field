# 日常任务改造:按 OK-AzurPromilia PR#30 的 DailyFeature 模式拆分全部子任务

## 目标架构(三层)

参考你写在 ok-ap PR#30 的模式,把 ok-end-field 日常从「DailyTask 继承 8 个 mixin + 组合 9 个 Feature 包装对象、全部配置堆在 DailyTask.json」改为:

1. **逻辑层(基本不动)**:`src/tasks/daily/` 下的业务 mixin(DailyBoatMixin、DailyCraftMixin、DailyLogisticsMixin、DailyOutpostMixin、DailyRewardMixin、DailyCreditMixin、DailyBuyMixin、DailyTradeMixin、DailyShopMixin、DailyBattleFeature、DailyDemoFeature)方法体保持原样——它们经 `__getattr__` 转发的运行期能力在任何 BaseEfTask 派生类上都成立。
2. **单元层(新增独立任务类)**:每个日常子任务 = `src/tasks/onetime/` 下的独立任务类,组合所需 mixin、持有自己的 `configs/<类名>.json` 与配置卡片、注册进 `src/config.py` 的 `onetime_tasks`。类名沿用上次拆分的孤儿配置名。
3. **编排层(瘦身)**:新增 `src/tasks/daily/daily_feature.py`(`DailyFeature`),`DailyTask.build_task_plan()` 经 `DailyFeature(self, XxxTask, switch_key="⭐…")` 接入;DailyTask 不再继承业务 mixin。

### DailyFeature 适配点(与 ok-ap 版的差异)
- ok-end-field 已有更优的账号覆盖机制(`AccountOverrideMixin._bind_account_aware_config_get` 直接给 `config.get` 打补丁),**不需要 ok-ap 的 `_sub_task_cfg` 取值链**,业务方法体零改动。注入改为:`impl.running = True`(账号覆盖查询的 gate)+ `impl.set_current_account(host.current_user, host.current_account_id)`(绑定账号上下文),`finally` 恢复原值。
- `_resolve_impl()` 沿用:从 `host.executor.onetime_tasks` 按 `isinstance` 找已注册实例;找不到记日志返回 False(该轮记失败,不中断其余任务)。
- `plan_item()` 支持可选谓词(利用 runner 已有的三元组语义)。
- **帝江号共享状态同步**:执行前后在 host↔impl 间复制 `_daily_boat_state_confirmed`,runner 的 `shared_state_task_keys`/`_prepare_shared_task_state` 原样保留,`TestDailyBoatState` 契约不破坏。

## 关键技术点:配置跨文件迁移的时序陷阱

框架 `verify_config` 会删除 `configs/DailyTask.json` 中不在 `default_config` 的键,而 DailyTask 在注册列表**第一位**、最先加载——若迁移发生在其后,参数键已被删,用户数据丢失。方案(仿 `global_config_store.py` 既有模式):

- 新增 `src/tasks/daily/split_config_migrator.py`:`DAILY_SPLIT_IMPORTS = {新类名: {"DailyTask": {旧键: 新键}}}` 声明表 + 一次性执行器(模块级完成标志 + 标记文件 `configs/_daily_split_migrations.json` + 迁移前备份 `configs/daily_split_migration_backup/`,setdefault 语义)。
- 在 `BaseEfTask.load_config()` **最前**调用 `maybe_run_pending_config_imports()`——首个任务(即 DailyTask)加载前完成全部导入,之后框架才 prune。
- 同一迁移器处理 `configs/account_scoped_overrides.json`:DailyTask 段下的参数键搬到新类名段(⭐开关键留在 DailyTask 段)。
- 三个 multi_selection 键(⭐帝江号收菜/⭐活动奖励/⭐地区建设)整体迁到子任务卡片,成为子任务参数;迁移时兼容旧布尔键(复用 `legacy_bool_switch_to_list`/`merge_bool_options`),对应 plan 项改用谓词判定(非空列表=启用)。DailyTask 旧的 `config_value_migrations` 在阶段二随之移除。
