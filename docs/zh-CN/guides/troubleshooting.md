# 常见问题与反馈

## 识别或点击不稳定

依次检查：

1. 分辨率是否为 16:9 且不低于 1600×900（900P）。
2. 是否使用默认亮度，并关闭显卡滤镜、锐化和画面悬浮层。
3. 游戏窗口是否未最小化，屏幕是否未锁定或熄灭。
4. 运行期间鼠标或手动输入是否干扰了前台游戏窗口。
5. 游戏帧率是否稳定，且游戏和程序权限是否一致。

## 安装或启动失败

- 确认使用最新版安装包，并将安装目录加入安全软件信任列表。
- 避免在 `Program Files` 或包含中文字符的目录运行程序。
- 源码运行时重新执行 `uv sync`，安装与当前项目匹配的依赖。
- 以管理员权限运行终端、IDE 和程序。

### 官方启动器要求与渠道启动方式

国服与 GRYPHLINK 国际服共用启动流程：从游戏目录的 `Endfield_Data/app.info` 读取 `Hypergryph` / `Gryphline` 公司标识，查找对应渠道的官方启动器，并要求 Windows Authenticode 有效、证书指纹在两服共用的官方白名单中，并核对所尝试启动器的已签名产品名。不会根据安装目录名字判断国服或国际服，也不会仅凭发布者名称放宽签名验证。两服的注册表安装位置分别查询；优先选择游戏对应类型，候选和缓存均校验共用官方指纹及所尝试的启动器产品名。查找、校验、创建临时父进程或创建游戏进程失败时，会清理本轮临时父进程，再尝试另一种官方启动器；两种类型各尝试一次。游戏进程一旦创建成功，后续错误或初始化超时不会触发再次启动。回退只更换临时父进程，游戏渠道、参数和日志公司目录不变。

程序为官方 `Games.exe` 创建专属的挂起临时实例，作为游戏的直接父进程；不复用或结束用户已有的启动器，也不需要点击“开始游戏”。请保留至少一种官方启动器，并把游戏路径设置为 `Endfield.exe`。两服直启都保留已有命令行参数，不额外注入语言或渠道参数。

两服都只读取当前渠道 `LocalAppDataLow/<公司标识>/Endfield/sdklogs/OneChannelLC.log` 中本次新增的完整日志行。收到时间属于本轮启动、PID 匹配本次临时进程的 `Parent process check success:<PID>` 后，立即回收本次专属 `Games.exe`，不再等待 `u8sdk_pc.log` 的 SDK 初始化完成；这只表示父进程检查通过，不表示游戏登录或所有资源加载完成。当前国际服实测在该信号后回收，后续 SDK 仍初始化成功；该实验不代表所有版本均已验证。

120 秒内没有成功信号时不凭超时强行回收，而是保持挂起父进程，等游戏退出后清理。读取日志或监视线程失败时，两服也共用备用监视及退出清理策略。下次 OK-EF 启动会检查 `owned_temporary_launchers/` 恢复记录：仅在原创建者已退出、PID/创建时间/完整路径匹配，且游戏或其他子进程均已退出后回收。无法确认身份或权限不足时保留记录并警告，不按进程名批量结束。

Steam 标准安装通过 Steam URI 启动；Epic 安装目录有 `.egstore/` 时通过 Epic 的安装目录 URI 启动。这两种渠道由各自平台管理，不创建上述临时父进程，也不结束 Steam/Epic 客户端。平台 URI 无法转发 OK-EF 自定义启动参数时会明确报错，请在平台客户端配置。Steam/Epic 的完整实机启动仍待验证。

无法读取或识别游戏公司标识，或两种官方启动器均不可用时，请修复安装或先用对应客户端手动启动。已经运行的游戏仍可由 OK-EF 识别，不会重复启动。启动异常请查看 `logs/ok-script.log`。

## 反馈问题

在 [GitHub Issues](https://github.com/AliceJump/ok-end-field/issues) 提交问题时，请提供清晰的错误截图或录屏、已脱敏的相关日志、复现步骤、实际结果、期望结果及软件版本。不要上传账号信息、个人路径、密钥或其他敏感数据。
