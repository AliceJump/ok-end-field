# 常见问题与反馈

## 识别或点击不稳定

依次检查：

1. 分辨率是否为 16:9 且不低于 1600×900（900P）。
2. 是否使用默认亮度，并关闭显卡滤镜、锐化和画面悬浮层。
3. 游戏窗口是否未最小化，屏幕是否未锁定或熄灭。
4. 运行期间鼠标或手动输入是否干扰了前台游戏窗口。
5. 游戏帧率是否稳定，且游戏和程序权限是否一致。

## 安装或启动失败

- 确认使用最新版安装包，并将安装目录加入安全软件信任列表。
- 避免在 `Program Files` 或包含中文字符的目录运行程序。
- 源码运行时重新执行 `uv sync`，安装与当前项目匹配的依赖。
- 以管理员权限运行终端、IDE 和程序。

### 国服游戏提示从官方启动器启动，或启动超时

国服新版 SDK 会检查游戏的直接父进程。本分支是 **PR #558 的实验性替代方案**：程序会定位并验证官方鹰角 `Games.exe` 的数字签名，创建**专属的挂起临时进程**作为游戏父进程。不会结束或复用用户已有的启动器进程，也不需要点击“开始游戏”。请保留官方启动器，不要将游戏路径改成启动器路径。

程序不会额外为 `Endfield.exe` 注入国服语言或渠道参数；已有的自定义启动参数（如 DX11）会原样保留。此自动启动方式针对国服官方启动器，尚未验证国际服或其他渠道。游戏已经运行时不会重复启动。

创建游戏后只读取 `LocalAppDataLow/Hypergryph/Endfield/sdklogs` 中本次新增的完整日志行；仅当 `OneChannelLC.log` 出现 `Parent process check success:<临时进程 PID>`，且 `u8sdk_pc.log` 出现 `OnU8V2InitCallback status :0`，才结束**本次创建的临时 `Games.exe`**。不靠固定等待判定成功。120 秒内没有得到完整证据时不会强行结束仍在运行的游戏对应的临时父进程，而是继续监视游戏退出，退出后清理本次创建的临时进程；若创建游戏前失败，或启动监视前确认游戏已经退出，也会清理。若游戏仍在运行而主监视器无法启动，会尝试启动备用监视器并移交进程句柄；若线程创建也失败，启动调用可能同步等待启动验证或游戏退出，而不直接丢失清理所有权。若无法获取游戏存活状态，仍可能需要手动清理。下次启动 OK-EF（或再次尝试启动游戏）时，还会检查上次创建的临时父进程记录。只有旧 OK-EF 进程已经退出、PID／创建时间／进程完整路径均匹配、且没有仍在运行的游戏或子进程时，才回收自己的挂起 `Games.exe`；不会按进程名批量结束。记录保存在应用配置目录的 `owned_temporary_launchers/`，身份无法确认或权限不足时跳过并记录警告。启动异常请查看 `logs/ok-script.log`，并检查官方启动器文件是否完整。

## 反馈问题

在 [GitHub Issues](https://github.com/AliceJump/ok-end-field/issues) 提交问题时，请提供清晰的错误截图或录屏、已脱敏的相关日志、复现步骤、实际结果、期望结果及软件版本。不要上传账号信息、个人路径、密钥或其他敏感数据。
