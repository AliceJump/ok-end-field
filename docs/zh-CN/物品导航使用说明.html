物品导航 · 使用说明

触发式任务「物品导航」会把你在游戏里的实时坐标，换算成指向目标物品最近点位的箭头， 叠加在游戏窗口上；走近后按住标记键即视为"已获取"，之后不再指向它。 本文覆盖两种位置来源（官方地图 WebSocket / 本地油猴脚本）、全部配置项、箭头含义、标记规则与排错。

1它做什么

任务每轮循环会：读取一次玩家坐标 → 在「选择物品」里筛出当前地图的点位 → 取水平距离最近的未标记点 → 在游戏窗口上画方向箭头与高差箭头 → 检测标记键是否被按住。

做

  • 持续指向最近的目标点位
  • 提示目标在你上方 / 下方（高差）
  • 提示附近还有哪些未标记点
  • 按住标记键把当前目标记为"已获取"

不做

  • 不自动移动、不自动寻路
  • 不自动拾取、不自动交互
  • 不识别游戏画面（needs_frame = False）
  • 不做跨地图 / 跨层的路径规划
因为它不截图

任务只吃 WebSocket 坐标，不走截图 + OCR/模板匹配管线，因此不占检测资源；但仍要求游戏窗口存在且可见。

2两种位置来源

位置数据的来源取决于配置里是否存在有效的 content，两者不会同时启用。

方式 A · 官方地图 WebSocket

用 content 走官方鉴权链路，换取 cred / signToken / dId， 再连接 wss://ws.skland.com/ws/v1/game/endfield/map 接收位置推送。

  • 不需要开浏览器、不需要油猴脚本
  • 需要账号已绑定终末地角色
  • 首次会自铸设备指纹并缓存到 configs/map_device_id.json

方式 B · 本地 WebSocket 服务

程序在 ws://127.0.0.1:3001 起一个服务端，由浏览器油猴脚本把官方网页地图收到的 原始位置 JSON 包转发过来。

  • 需要在浏览器里打开网页地图并保持标签页存活
  • 需要安装 Tampermonkey 并导入仓库内脚本
  • 不需要登录态之外的任何凭据
回退只发生在"没有 content"时

如果已经配了 content（或地图账号能解析出 content），但官方鉴权或连接失败， 当前运行不会自动改用本地 WS。要切回本地模式，请清空任务的 content 并清空「地图账号」。

该填哪个？

已经用账号配置页同步过地图，就选「地图账号」，最省事； 只想临时用一次、或想手动指定凭证，就把 content 直接贴进任务配置。 不想碰官方接口，就两个都留空，走本地油猴脚本。

5上手 A：本地油猴脚本（推荐先跑通）

  1. 安装 Tampermonkey 在浏览器扩展商店安装油猴扩展，并确认它处于启用状态。
  2. 导入转发脚本 在任务配置里点「油猴脚本帮助」按钮，会自动定位到脚本文件；把 assets/scripts/endfield-ws-position-relay.user.js 导入 Tampermonkey 并启用。
  3. 打开网页地图 访问 https://game.skland.com/map/endfield。脚本会每隔 1 秒尝试点击"位置同步"开关， 最多尝试 30 秒；若中途超过 5 秒没收到有效消息，会自动重试恢复。
  4. 确认脚本已连上本地服务 浏览器控制台应出现 [坐标转发] 已连接到本地服务器 ws://localhost:3001。 如果显示"本地WS断开，准备重连"，说明程序端服务还没起来（先启动任务即可）。
  5. 在任务里选择物品 「选择物品」里勾选你要找的东西（例如 见闻辑录、储藏箱III、醚质）。
  6. 启动任务并保持游戏在前台 任务日志里会出现 ItemNavigatorTask 启动 - 正在启动WS服务 与 ws://127.0.0.1:3001。 切回游戏窗口，左上角即可看到箭头。
脚本做了什么

它劫持网页地图的 WebSocket.addEventListener，把 /ws/v1/game/endfield/map 上收到的 原始 JSON 包（心跳包 type: 4 除外）原样转发到 ws://localhost:3001， 因此程序拿到的是与官方客户端一致的数据格式。

6上手 B：官方地图同步

  1. 准备 content 二选一：把 content 直接贴进任务配置，或保存到账号配置页再在任务里选账号。 两种方式都需要先按下面的步骤把 content 取出来：
    1. 打开浏览器，按 F12 打开开发者工具。
    2. 访问 https://game.skland.com/map/endfield 并登录。
    3. 切到 「网络 / Network」 标签，在筛选框里输入 https://web-api.skland.com/account/info/hg/check。
    4. 在筛选后的请求列表里选中该请求，从 「响应 / Response」 中取 data.content 的值（是一长串字符串）。
    5. 把该值填入任务的 content 参数；或填入账号配置页的 地图同步 content，再回到任务用「地图账号」选择该账号。
  2. 选择账号 用账号配置页方式时，在「地图账号」下拉框里选中对应账号。
  3. 选择物品并启动任务 日志里会出现 ItemNavigatorTask 启动 - 正在启动官方地图WS客户端， 随后是 [地图WS] 已解析角色: serverId=… roleId=… 与 [地图WS] 已连接。
  4. 等待第一条位置 收到位置后日志会打印 [地图WS] 收到位置: mapId=… pos=(x,y,z)，任务显示栏同步更新。

鉴权链路与首次铸造

方式 A 的内部流程（了解即可，出问题时对照日志）：

content ──HG 授权接口──▶ oauth code
        ──generate_cred_by_code + dId──▶ cred / token(userId)
        ──/api/v1/websocket/token──▶ ws token
        ──连接 wss://ws.skland.com/...──▶ type:2 认证成功
        ──定时 type:1011 初始化 + type:3 心跳──▶ type:1012 位置推送
关于设备指纹 dId

接口要求 dId 是真实签发的设备指纹，随机串会返回 10001 设备信息无效。 程序会自动开一个匿名浏览器配置访问官方地图页完成注册，并缓存到 configs/map_device_id.json。 如果已存的 dId 被风控拒绝，程序会自动清除本地缓存、停掉旧客户端，并在稍后重新铸造重试。

7画面元素与箭头图例

所有箭头绘制在一个依附于游戏窗口的透明叠层上，只有游戏窗口处于前台时才会显示。

绿色方向箭头 从窗口左上角固定原点发出，指向当前最近目标的方向。长度 = 水平距离 × 1.144，但封顶为窗口短边的 8%——所以它只表达方向，不表达精确距离。
绿色高差箭头（同一原点） 向上＝目标在你上方，向下＝在下方。长度按 |ΔY| / 30 归一化，最长到窗口高度的 8%；|ΔY| 越大越长，到 30 以上不再变化。
黄色小箭头（附近点提示） 水平距离 ≤ 75.5 的未标记候选点都会各画一个小箭头，位置按相对坐标等比映射到原点周围，用来提示"这一片还有别的"。它们不代表当前导航目标。
浮层目标信息（可关闭） 在箭头下方直接显示物品名、水平距离、八方位与上下高度三行。方位与方向箭头共用同一坐标系，两者始终一致。由「浮层信息」开关控制，黑色底板与文字的透明度、字号可分别调整。
任务显示栏 格式为 目标=物品名 距离XZ=数值 角度=数值°；进入接近状态后追加 接近: 高差Y=数值 (上方/下方/同高)。想看准确距离就看这里。

8标记"已获取"的规则

标记机制的设计目的是：你亲手走到点位旁边确认拿过了，程序就不再指向它。

环节条件 / 行为
进入接近状态当前最近目标的水平距离 ≤ 20 时，锁定该目标为待标记对象
开始计时按下「标记按键」的那一刻开始计时
标记成功连续按住时长达到「标记按住时长」（默认 2 秒），且期间没有松开、没有走出 20 范围
取消计时期间任意一帧检测到松键，或离开 20 范围 → 本次锁定作废，需重新按住
写入位置configs/marked_points.json，按地图 ID 分组
记录键物品名|x|y|z（坐标保留 3 位小数）——含物品名，所以不同物品同坐标不会互相覆盖
写盘时机标记后延迟约 3 秒合并写盘一次，减少 IO；采用"先写临时文件再替换"的原子写入

重置标记

已标记的点会一直被跳过。要重新导航某个物品，需要清理记录：

configs/marked_points.json
{
  "map02": [
    "见闻辑录|123.456|78.901|-234.567",
    "储藏箱III|…"
  ]
}
  • 删掉整个文件 → 所有地图的标记全部清空。
  • 删掉某个地图 ID 的键 → 只清空该地图。
  • 删掉某一行 → 只让那个点位重新参与导航。
  • 标记文件仅由 ItemNavigatorTask 在任务初始化时加载；修改文件后需要重新开始任务才能生效。
旧路径会自动迁移

如果检测到旧路径 assets/items/map/marked_points.json，程序会自动迁移到 configs/marked_points.json 并删除旧文件。

10常见问题

任务在跑，但游戏窗口上完全看不到箭头
  1. 游戏窗口不是前台窗口 — 叠层只在游戏窗口为前台时显示，切出去就隐藏。先点回游戏。
  2. 没有位置数据 — 看任务显示栏：WS位置数据待接收... 说明本地服务在监听但没人连； 地图WS位置数据待接收... 说明官方客户端还没收到推送。
  3. 点位数据里没有你选的物品 — 当前地图不含该物品时不会有目标。
  4. 窗口尺寸读取失败 — 极少数情况下窗口客户区尺寸为 0，箭头会被跳过。
显示"WS位置数据待接收…"，但油猴脚本已经启用了
  • 确认浏览器控制台里有 [坐标转发] 已连接到本地服务器 ws://localhost:3001。
  • 确认任务已经启动过——本地服务是任务启动时才创建的，脚本连不上会每 3 秒重连。
  • 确认网页地图的"位置同步"开关是打开的（脚本会自动点，但若页面结构变化可能失效）。
  • 检查本机防火墙 / 安全软件是否拦截了 3001 端口。
显示"无候选物品"或"无未标记候选"
  • 无候选物品：「选择物品」为空，或当前地图里没有你勾选的物品。
  • 无未标记候选：该地图上你选的所有点位都已经标记过了。清 configs/marked_points.json 或删掉对应地图的键即可。
官方地图模式认证失败，日志报 10001 / 设备信息无效

这是 dId 被风控拒绝。程序会自动清除 configs/map_device_id.json、停掉旧客户端，并在下一个触发周期重新铸造。

如果持续失败，检查：本机是否装了 Edge 或 Chrome、能否访问 fp-it.portal101.cn、网络是否有代理拦截。

任务显示"游戏窗口不存在，等待重新选择/启动游戏"

程序检测到游戏窗口不存在或不可见，已主动停止位置同步并清空箭头。重新启动游戏、让窗口可见后，任务会在下一轮循环自动恢复。

地图 WS 客户端自己停了

两种自动回收条件：

  • 游戏窗口消失或不可见（日志：物品导航：游戏窗口不存在或不可见，地图WS客户端停止）。
  • 10 秒内没有任何任务读取位置（日志：[地图WS] 10秒内没有任务读取位置，客户端自动停止）——例如任务被停掉后，客户端不再空转。

两种情况都会在任务下一轮循环按需重建连接。

按住标记键没反应，标记不上
  • 必须水平距离 ≤ 20 才算接近，才允许标记。
  • 必须连续按住「标记按住时长」设定的秒数（默认 2 秒）——中间松开一帧就作废，注意别连点。
  • 「标记按键」只支持单个字符，填 F1 之类不会生效。
  • 按住时长可以调：改「标记按住时长」即可（每轮生效，无需重启任务）；填 0、负数或非数字会回退为默认 2 秒。
已配置 content，但官方 WS 连不上，能不能自动改用本地脚本？

不能。回退只在"解析不出 content"时发生。要切本地模式，请清空任务的 content 并把「地图账号」也清空。

11限制与注意事项

  • 不寻路。只给方向与高差，怎么走过去由你决定；跨层、绕障都不在职责内。
  • 方向箭头长度封顶。距离超过阈值后箭头长度不再变化，别用它估距离——看任务显示栏的「距离XZ」。
  • 同一时刻只有一个目标。始终指向水平距离最近的未标记点，不排队、不轮换。
  • 需要游戏窗口存在且可见。虽然不截图，但叠层与窗口存活检测都依赖窗口句柄。
  • 箭头需要游戏窗口在前台。看攻略、切浏览器都会让箭头隐藏。
  • 标记是手动的。程序不会替你判断"是否真的拿到了"，按下标记键就等于你确认过了。
  • 按住时长过短会误标。「标记按住时长」可以调到很小，但越短越容易在你只是路过、随手按键时把点位标成已获取。
  • 点位数据是离线快照。游戏版本更新后点位可能偏移或新增，需要更新 assets/items/map/ 下的数据文件。
