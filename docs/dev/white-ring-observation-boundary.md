# 白圈观测、场景推断与执行规则的边界

2026-10-16。白圈检测并入现有BattleMixin战斗监测，不新增线程、截图循环、检测区域或识别种类。需要开启现有技能时间排轴；关闭时的旧推荐技能路径不改变。

## 数据怎样进入真实排轴

```text
现有当前帧 + 固定按钮小框
→ BattleMixin.observe_battle_skill_highlights 一批采样各槽
→ BattleHighlightState 保存 visible=true/false/unknown、按钮合同、时间
→ BattleHighlightStability 通过不同新帧校准稳定可见状态（原始观察仍保留）
→ BattleConditionEvaluator 推导当前场景条件与队伍模型内OR收窄
→ BattleConditionAssessment / ForecastConditions
→ 强化报价、防溢出比较、ReleaseBurstPlanner后续动作排序
→ 独立执行规则 + 原SP/动画/冷却检查
```

每个战斗循环获取的新帧均批量采样四个固定小框，短队仍按右锚定人数映射有效槽位；同一张截图的重复查询复用批次，不重复计帧。暂停敌人调度期间也采样；终结动画不可用时不建立场景事实，恢复时清理旧状态。没有已绑定条件时仍可读取原始批次，但不凭无合同白圈推导机制。批次缺槽、空结果或未知会撤回为未知，不用旧true补齐。兼容仅提供单槽hook的测试/离线输入。

2026-10-21多帧合同：连续2个新帧亮才确认true；连续至少3个新帧暗，且暗段跨度至少150ms，才确认false。短暂低谷保留之前稳定值。闪光、无效图、分辨率/按钮合同变化、超过600ms采样空档均清理旧证据为未知。使用现有截图实例及框架捕获时间戳识别新帧，重复读取同一截图不累计；框架复用图像缓冲但捕获时间变化时可以累计。这是可调整的视觉去抖参数，不是机制TTL或游戏脉冲周期的原生证明。

战技资源/动作锁可行后，按前再获取4张新帧，帧间隔50ms，总额外等待约150ms加截图耗时；继续批量采样全队。稳定条件相比搜索时发生变化则保留技力、重新报价选招；同帧时间戳刷新或单帧低谷不强制撤单。复查后再次核对技能变体、费用及动作锁，避免期间姿态到期仍按旧免费段。没有新线程或第二个后台循环，也没有提高白色阈值或扩大ROI。

2026-10-19补充：终结技恢复已推进战斗画面，立即清除动画前的批次观察，恢复后的同一步防溢出评分退回未知条件。下一普通step才重新统一采样，不在终结恢复时追加第二批扫描；不会因此删除真实buff或把对应条件判为false。

`BattleHighlightObservation`只含`skill_ids/condition_json/visible/observed_at`。不保存inference、不运行队伍闭包、不使用ready命名，也不把亮圈当作能放招。`BattleConditionEvaluator`才运行原生谓词推断；只把直接蕴含的tag/buff作为带按钮范围的场景事实，队伍模型收窄仍单独保存，不升级为已观测敌人事实。

伤害消费者要求`BattleConditionAssessment`，传入原始亮圈对象不能直接启用额外伤害或创建预测条件。这是运行路径的类型边界，不只是新增一个未消费的数据集。原有安塔尔/赛希起手后保留已审核的条件证据、未知动作清除预测条件，继续影响后续真实候选和排序。

## 庄方宜是明确的执行合同

先前用户批准的庄方宜“白色才按、有效白色消失接受、未知超时不消费免费机会”保留，但由`battle_execution_policy.py`中的独立合同声明。通用观测和推断模块不知道庄方宜，也不执行按键或确认释放。普通角色的执行合同不以亮圈为许可；即使亮圈，SP不足、动作锁或收益较低时也不抢放。

其中“白色”与“消失”现在读取稳定状态。发送按键时重置暗帧计数，按前低谷不参与按后确认；必须累计按后的连续暗帧及150ms跨度，不能暗一帧就确认。沿用原0.8秒确认超时与失败提示优先级；超时或未知不消费免费机会。仍不是额外独立的释放成功检测。

没有将白圈熄灭解释成buff消失、OR所有分支false、命中/消费/返还已经发生。没有跨不同按钮推定推荐目标是同一个敌人。通用跨角色EnemyState共享和所有强化机制的倍率/producer仍未完成，本批不把这些后续工作说成已接通。
