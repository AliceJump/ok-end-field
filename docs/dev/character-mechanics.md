# CharacterMechanic v1

技能时间排轴不能再假设“一个角色 = 一个战技按钮 + 一个固定伤害数字”。

本层从 `assets/data/character_skills/*.json` 的结构化效果、强化条件、专精3数值和技能文案中保留主C机制语义；原生帧时序仍由 `skill_timing.py` 提供。

## 第一批机制

- 弭弗：三段战技状态机。断云 100 SP、返还 50；追形 50；满足至少 3 层破防后才有开天 50。连携/终结技会把战技直接替换到追形。
- 提弗洛斯：战技进入浮空，最多 5 次空中普攻；自然附着逐层消费并转为启示；8 启示通过连携转为 4 猎矢并重置空中普攻；终结技给 2 猎矢并重置浮空段。
- 庄方宜：连携把电磁附着转成/升级导电；战技消费导电并生成青霆剑；终结技状态内首次战技免费、不消费导电并固定生成 3 剑。
- 伊冯：战技消费全部法术附着后冻结；连携依赖冻结目标的主控重击；终结技强制主控 7 秒，最后一击是重击并在冻结存在时追加伤害、消费冻结。

## v1 运行时规则

1. 上述角色出现时，旧 `optimize_cycle` 不得把角色压成单个 `CastOption`，因此不会再生成只保留少数高纸面 DPS 战技的子集轴。
2. 弭弗/提弗洛斯的原生入口技能即使不是 `*_normal_skill` 也必须进入队伍战技候选。
3. 弭弗运行时按原生 `normalskill_1/2/3` 的费用和 allow-next 窗口推进；第一段按 100 SP 门槛、50 SP 净消耗确认，并优先尝试追形。开天缺少破防层数视觉证据时不强制续按；未确认会回到首段，避免锁死。
4. 庄方宜终结技后优先尝试一次 0 SP 的强化战技。
5. 伊冯终结技成功后保护约 7 秒自身主控普攻窗口；只抑制伊冯自己的战技以避免打断该段，其他角色战技、连携和终结技都可后台并行。

## 尚未完成

- 连携 HUD 目前不能识别具体 owner，因此弭弗“连携后直接追形”暂时不能可靠地只更新弭弗状态。
- 提弗洛斯的启示/猎矢数量、庄方宜导电等级/青霆剑数量、伊冯目标附着层数还没有画面状态检测；现阶段依赖游戏自身的连携/终结技就绪 HUD 做触发证据。
- 连携释放不能因为任一队员缺失 native link timing 就全局关闭。洛茜的原生连携入口是 `combo_1_skill -> combo_2_skill -> combo_3_skill`，不是标准 `combo_skill`；运行时需解析编号入口，并且 HUD 已确认连携就绪时即使仍有个别角色缺 timing，也只能降低时间轴保护精度，不能阻断 E。
- 机制数据稳定后再定义 runtime binary schema；二进制必须保留这些状态与 transition，而不是只存 battle/link/ult 三个伤害值。


## 动态技力监测与防溢出

- 排轴主循环仍保持 50ms 级响应，但精细技力条扫描不再每轮都执行。
- 防溢出不再等到 295/300 SP 才开始。根据当前存活队伍已知/保守上界的主控重击回技量，动态计算 250~275 SP 的压力线；例如最大突发回技 25 SP 时压力线为 265 SP。
- 距离压力线 50 SP 以上时每 0.25 秒精细读一次；进入中警戒区后约每 0.15 秒；到压力线以上约每 0.08 秒，并在每个调度帧做第 3 格满格快速探针。
- 一旦越过压力线就提前尝试泄技力：当前计划战技能放则优先释放；当前槽位因为短退避、状态或冷却不可用，则在其他非复杂机制槽位中按战技伤害 / handoff 插入，原计划 cursor 不前移。TeamPhasePlanner 的 burst reserve 仍可否决会破坏爆发储备的泄技力动作。
- 战技按键 0.8 秒内没有观测到有效 SP 消耗时，不再保留一个“可能已经开始”的完整 native 时间轴。清除这条未证实时间轴，仅给该槽位 0.20 秒短退避；这避免长时间轴角色一次失败按键把全队调度锁十几秒。
- 死亡槽位不再由单次稳定 `?` 直接确认。必须在独立的约 1 秒刷新周期中连续 3 次同位置未知才屏蔽；任何一次重新识别到原角色都会清空怀疑计数。
- 终结技 HUD 恢复后立即强制刷新一次技力并再次执行机制战技/高技力抢占，避免动画期间积满后还等待下一轮。


## TeamPhasePlanner v1

复杂机制不再继续塞进旧的稳态 `evaluate_cycle()`。新增队伍级有限窗口模型：

- `TeamCombatState`：共享 SP、PREP/CHARGE/BURST_READY/BURST/RECOVER 阶段、当前 burst、动作进度、失效槽位，以及后续私有资源/敌方状态扩展位。
- `BurstAction`：动作所属槽位/角色、battle/link/ult/normal、SP 门槛、实际消耗、确定返还、持续时间、阶段伤害（可未知）、requires/consumes/produces。
- `BurstPlan`：允许多个槽位共同参与；从整段动作的 SP 流倒推 `min_start_sp`，而不是固定写死 300。
- SP 预算默认不把 8 SP/s 自然回复算作必要条件；自然回复只作为窗口里的额外余量，因此计划不会靠理想帧时序才能成立。
- 若阶段伤害数据不足则保持 `expected_damage=None`，不拿旧的整技能 DamageQuote 强行拆给多段状态技能。

### 当前可执行范围

弭弗三段战技是第一条 runtime-executable burst：

```
断云: gate 100, cost 100, refund 50
追形: gate 50,  cost 50
开天: gate 50,  cost 50
```

整段从共享 SP 倒推得到：

```
min_start_sp = 150
expected_end_sp = 0
```

当现有伤害排序把弭弗视为首要核心槽位时，运行时会进入 CHARGE：

- 未达到 150 SP 时，普通战技不能把共享 SP 花到 reserve 以下；
- 达到 150 SP 后进入 BURST_READY，并优先开始弭弗链；
- 爆发过程中只允许下一合法 burst 动作或零净消耗动作插入；
- 条件开天未确认时重置到首段，避免卡死；
- 弭弗终结技把战技 shortcut 到追形时，同步把 burst action index 移到追形，剩余起手目标重新计算为 100 SP。

为了避免“队伍里只是带了一个机制角色就劫持全队 SP”，v1 仅在 runtime-executable burst 的 owner 与当前伤害排序第一槽一致时自动选择该 burst。多角色 `BurstPlan` 的数据结构和 SP 预算已经支持，但实际自动选择要等参与者的关键状态/连携 owner 有可靠观测证据后再开启。

### 与旧伤害模型的边界

`timing_dps.py` 继续作为简单队伍的稳态 fallback；`TeamPhasePlanner` 负责有限爆发窗口和共享资源保留。二者不再互相假装：

- 稳态模型回答“长期重复哪个循环平均收益高”；
- 阶段模型回答“为了下一次完整爆发，现在需要保留多少共享 SP、哪些动作可以插入、什么时候开始整段 burst”。

后续阶段伤害应由状态感知的 ActionOutcome 提供，而不是把 `DamageQuote.battle` 生硬拆给每一段。


## 隐藏资源的概率期望

无法从 HUD 可靠识别的层数，不再按满层口径估值，也不直接丢弃。

运行时新增 `HiddenStateExpectation`：

- 有明确上限的隐藏资源保存完整离散分布 `P(0)..P(N)`；
- 战斗入口明确为 0 的自身资源从 0 层开始；
- 如果队伍具备某元素附着 producer、但当前敌方附着层数不可见，则对 0..4 层使用最大熵先验；若队内无人能产生该附着，则概率直接为 0；
- 确定产生的资源按概率 1 更新；
- 依赖隐藏前置条件的资源增减，把前置条件当前概率向后传播；
- 数据只知道“会生成 1..3 层”时，默认在合法范围内均匀分布，不假装一定取 3；
- 完全没有证据的二值条件才回退最大熵先验 0.5。

必须区分两个不同量：

```
P(达到满层)
E[层数] / 最大层数
```

例如 0..4 层完全未知时：

```
P(4层) = 20%
E[层数] = 2
期望层级比例 = 50%
```

“每层线性增加伤害”的技能使用 50% 的层级比例做期望；“只有满层才触发”的效果使用 20% 的满层概率。两者不能混用。

### 当前接入

- 提弗洛斯：有自然附着提供者但层数不可见时，`风矢穿林` 在保守/满口径之间按自然附着期望层级插值；没有自然提供者则直接使用下界。
- 伊冯：项目审阅数据确认法术附着上限为 4。战技专精3为基础 400% 口径，并且每消耗 1 层额外 +200%；因此可直接从 `P(0..4)` 计算逐层期望，不能使用满 4 层伤害作为默认值。
- 庄方宜：导电等级上限按法术异常全局 4 级建模，普通惊霆诀不默认导电满级；但终结技后的首次惊霆诀数据明确“免费且必定生成 3 柄青霆剑”，这一步仍按确定事件而不是概率事件处理。
- 核心槽位的临时伤害排序也改用隐藏状态期望值，因此不会先用满层伤害把某角色误判成主C，再反过来让全队为这个错误主C保留 SP。

`BurstAction` 同时保留：

```
damage_low
expected_damage
damage_high
full_probability
expected_fraction
damage_basis
```

日志会输出隐藏状态动作的下界、期望、上界、满层概率和期望层级比例，便于后续拿实战记录校准先验/转移概率。

这仍然是 v1：当前概率来自结构化机制、队伍 producer 和动作历史；没有实战统计证据时不会伪造“命中率 73%”之类精确数字。后续若能从日志统计某条件的真实触发率，可直接替换最大熵先验而不改 planner 接口。


## 敌人存在与技能受阻观测钩子

先保留运行时语义，具体固定坐标/阈值后续拿实战画面再填，不在没有样本时猜检测参数。

### 敌人是否仍在场

BattleMixin 新增 `probe_enemy_presence()`，返回：

```
UNKNOWN  当前还没有可靠观测
PRESENT  固定区域明确看到敌人证据
ABSENT   已检查固定区域但没有敌人证据
```

后续 detector 的预定证据：

- Boss：屏幕上方固定区域的大红色 Boss 血条；
- 小怪：场景内固定样式的小血条/敌人标识。

只有在外层仍处于战斗 HUD、且 detector 明确返回 `ABSENT` 时，时间排轴才进入“场内无敌人暂停”：

- 松开普攻；
- 不释放战技、连携、终结技；
- 不执行周期锁敌输入；
- 不结束战斗，只等待敌人重新出现；
- `active_time()` 继续推进，不修改 `state_until`、cooldown 或 native timeline 起始时间，因此这段等待会真实消耗角色状态/技能窗口；
- 一旦进入 ABSENT 暂停，UNKNOWN 不会误恢复，必须等明确 PRESENT。

当前 hook 默认返回 UNKNOWN，因此在 detector 尚未实现前不会改变现有实战行为。

### 顶部白字：技能受阻原因

BattleMixin 新增 `probe_combat_action_block_reason()`，后续固定检查屏幕中上方短白字区域，预留两类结果：

```
TOO_FAR       离敌人太远（较短文本）
DURING_SKILL  当前技能期间无法释放此技能（较长文本）
```

可以先按白色文本带的长度/几何区分，必要时再补 OCR，不要求一开始就做全屏文字识别。

调度器已经接入反馈语义：一次动作尝试后的 1.2 秒内若命中提示，会撤销“技能已开始”的未证实时间轴；战技进入 0.2 秒短退避，避免错误 cooldown / state 继续污染后续排轴。

`TOO_FAR` 另外调用 `recover_target_too_far()`。该 hook 当前故意是 no-op，预定实现顺序为：

```
锁定/对准目标
-> 等待视角转向稳定
-> 长距离向前冲刺
-> 回到正常战斗调度
```

`DURING_SKILL` 不触发位移恢复，只取消失败尝试并稍后重试。
