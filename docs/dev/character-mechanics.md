# CharacterMechanic v1

技能时间排轴不能再假设“一个角色 = 一个战技按钮 + 一个固定伤害数字”。

本层从 `assets/data/character_skills/*.json` 的结构化效果、强化条件、专精3数值和技能文案中保留主C机制语义；原生帧时序仍由 `skill_timing.py` 提供。

## 第一批机制

- 弭弗：三段战技状态机。断云 100 SP、返还 50；追形 50；满足至少 3 层破防后才有开天 50。连携/终结技会把战技直接替换到追形。
- 提弗洛斯：战技进入浮空，最多 5 次空中普攻；自然附着逐层消费并转为启示；8 启示通过连携转为 4 猎矢并重置空中普攻；终结技给 2 猎矢并重置浮空段。
- 庄方宜：连携把电磁附着转成/升级导电；战技消费导电并生成青霆剑；终结技状态内首次战技免费、不消费导电并固定生成 3 剑。
- 伊冯：战技消费全部法术附着后冻结；连携依赖冻结目标的主控重击；终结技强制主控 7 秒，最后一击是重击并在冻结存在时追加伤害、消费冻结。

## v1 运行时规则

1. 上述角色出现时，旧 `optimize_cycle` 不得把角色压成单个 `CastOption`，因此不会再生成只保留少数高纸面 DPS 战技的子集轴。
2. 弭弗/提弗洛斯的原生入口技能即使不是 `*_normal_skill` 也必须进入队伍战技候选。
3. 弭弗运行时按原生 `normalskill_1/2/3` 的费用和 allow-next 窗口推进；第一段按 100 SP 门槛、50 SP 净消耗确认，并优先尝试追形。开天缺少破防层数视觉证据时不强制续按；未确认会回到首段，避免锁死。
4. 庄方宜终结技后优先尝试一次 0 SP 的强化战技。
5. 伊冯终结技成功后保护 7 秒强制主控普攻窗口；其他角色战技/连携仍可并行，但不插入其他终结技。

## 尚未完成

- 连携 HUD 目前不能识别具体 owner，因此弭弗“连携后直接追形”暂时不能可靠地只更新弭弗状态。
- 提弗洛斯的启示/猎矢数量、庄方宜导电等级/青霆剑数量、伊冯目标附着层数还没有画面状态检测；现阶段依赖游戏自身的连携/终结技就绪 HUD 做触发证据。
- 机制数据稳定后再定义 runtime binary schema；二进制必须保留这些状态与 transition，而不是只存 battle/link/ult 三个伤害值。


## 动态技力监测与防溢出

- 排轴主循环仍保持 50ms 级响应，但精细技力条扫描不再每轮都执行。
- 最近一次精细结果低于 2 格时，每 0.25 秒更新一次精细值；达到 2.x 格后，每 0.10 秒更新精细值，并且每个调度帧只额外检查第 3 格是否已满。
- 第 3 格一旦确认满，当前帧立即进入防溢出抢占，不等待下一次精细扫描。
- 满技力时先尝试当前计划战技；若该槽位因状态、冷却或同角色窗口不可用，则在其他非复杂机制槽位中按战技伤害 / handoff 选择可释放项临时插入，原计划 cursor 不前移。
- 终结技 HUD 恢复后立即强制刷新一次技力，并再次执行机制战技/满技力抢占，避免动画期间积满后还等待下一轮。
