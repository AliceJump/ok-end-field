# 伤害增益接入梳理

本审计针对 PR #436 当前代码与本地数据快照（2026-10-03），说明哪些数值进入了伤害基准、哪些效果尚未进入逐次命中的结算。管理员采用用户指定的 P3；普通六星 P0、四五星 P5、各槽战斗天赋最高阶。潜能与天赋的基准选择不等于它们的全部效果已自动应用。

## 当前覆盖

| 内容 | 当前状态 | 主要缺口 |
| --- | --- | --- |
| 基础攻击、武器攻击、主副能力 | 32角色固定基准重算，计入属性节点及已选潜能的常驻属性 | 余烬80级/R9；其余暂沿用原90级/最高技能列口径 |
| 武器、装备的常驻攻击与伤害加成 | 已识别的常驻词条参与计算 | 依赖触发条件的词条跳过；不能视为装备全部效果已计算 |
| 各技能实际伤害元素 | 静态基准按技能元素选择对应加成 | 多段、替换攻击需要逐段保留类型 |
| 常驻暴击率、暴击伤害 | 静态期望已计算 | 伊冯等战斗中逐层获得的暴击增益没有逐击结算 |
| 技能给予的增幅、脆弱、攻击/暴击增益 | 16角色的31个已有效果均有明确绑定；等级可选择，引用可追溯 | 诀的4条形态分支、提弗洛斯箭阵时长仍标为未决，不能当作确定加成 |
| 敌方脆弱、其他承伤提升 | 共用结算按敌人、伤害类型和命中时间读取 | 普通战技估计已执行明确的基础命中生产者；条件分支仍需动作结果 |
| 天赋、潜能的攻击提升等效果 | 13条定义已有可执行修正规则，包含管理员P3的自用/队友增益、骏卫独立计时士气等 | 其他原生 modifier、监听条件及追加攻击尚未全部映射 |
| 连击、破防、附着与反应 | 有局部状态/规则及保守或满口径估计 | 未与全部技能、增益、持续时间及资源变化串成统一战斗过程 |
| 抗性、防御、失衡窗口、条件装备 | 部分公式在机制文档中 | 当前静态直接伤害为标准假人口径，不能代表具体敌人和实际窗口 |

`compute_fixed_damage_baseline.py` 生成 `fixed_damage_baseline.json`：固定武器、套装、主副能力、属性节点、潜能常驻属性和已核实的黎风常驻攻击天赋先计算完成，保留攻击白值、固定攻击、攻击百分比和属性系数等分量。常驻战技伤害等加成与常驻增幅分开计算；条件武器/套装不提前假设触发。产物不包含拼接的普攻/连携循环，也不默认满连击或私人资源。

`timing_dps.load_damage_quotes()` 默认读取新固定基准；普通战技循环估计调用 `TimedDamageState`，按时序更新明确的基础 cast/hit 生产者，并将增幅、脆弱等收益应用到后续匹配伤害。重复阶段判定包含增益剩余时间，支援动作先为紧随的匹配攻击准备SP/CD，避免增益在等待中耗尽。旧 `damage_baseline.json` 仍供原有 `skill_rotation.py` 和复杂阶段诊断读取，不将旧满口径机械地搬到新固定基准。

估计得到的支援SP门槛及后续CD要求由 `TimedCombatLogic` 执行；后续队友死亡时不以该门槛永久阻塞存活角色。增益在模拟中的生效点仍是时间估计，不表示实战按键成功已经证实每一段命中。

`damage_resolution.py` 支持逐击结算、主控/本人/全队/其他队友/指定敌人、同源刷新、不同来源区分、独立层数计时、暴击上限、非暴击伤害和未知参数反馈。攻击提升作用于攻击白值，固定攻击和已计算的属性系数不重复乘算。缺少强度、时长或属性输入时返回未定价结果，不用零或标记1代替。

当前排轴仍将普通战技作为一次伤害报价，使用现有handoff近似生效点；原生逐段命中时间线尚未接入。条件事件、私人姿态、概率结果、场地进入/离开及全部被动监听尚未自动从实战反馈驱动，不能据此宣称完整战斗模拟已完成。

已有两个局部 `TeamCombatState`：`combat_model.py` 管理共享连击池，`team_phase_planner.py` 管理阶段、SP、私人资源和状态标记。它们尚未形成统一的敌人、角色、场地、计时增益与逐击伤害状态；不能把已有类名当成完整机制模拟已接入。

## 数据存在但尚未绑定的实例

以下数字取自当前 canonical 技能等级表的最后一列，表示该列的技能口径；不替代后续按实际技能等级取值。

- 安塔尔战技：电磁、灼热脆弱各10%，持续60秒。对应效果仍为 `value=1`、`duration=null`。
- 安塔尔终结技：全队电磁、灼热增幅各20%，持续12秒。对应效果仍为 `value=1`、`duration=null`。
- 艾尔黛拉战技：先消费腐蚀才施加物理与法术脆弱，等级表为20%、30秒；分支中的效果强度、时长尚未绑定。
- 赛希战技：满血治疗触发法术增幅，等级表为15%、25秒，受益者是触发治疗的主控干员。
- 赛希终结技：寒冷、自然增幅基础24%，每点智识额外0.03%，智识部分上限36%，持续12秒。需要读取赛希属性，不能只使用基础24%。

上面示例记录的是绑定前的缺口。本次通过 `damage_modifier` 中的等级表/最高阶被动参数引用绑定真实值，遗留标记1改为null；`SkillEffect.damage_modifier` 保存有单位和乘区的解析结果。默认与原固定基准一致取最高技能列，也支持显式R9；潜能增量、倍率和持续时间修正按实际选择生效。`BUFF_*_UP` 名称不作为乘区判断依据。

## 结算要区分的层次

1. 力量、智识等主副能力提升先改变角色属性，再影响面板攻击力及读取该属性的天赋/技能。
2. 攻击力提升改变攻击力；元素伤害加成进入对应伤害加成计算。
3. 元素/法术增幅按其实际适用伤害类型作用于输出；与普通装备伤害加成分别记录。
4. 脆弱施加在敌人身上，只影响匹配类型的命中。法术脆弱不覆盖物理伤害。
5. 其他承伤提升、连击、失衡及抗性等分别保留来源与分类，不能把所有百分比相加。具体叠加规则、快照时点与上限按原生数据核验；旧机制文档不能替代当前定义。

## 后续顺序

接下来完成未决的形态/场地参数、其余天赋与条件武器/套装的原生运算和叠加规则，再将已绑定的事件接到统一动作结果和实际逐段时间线。消费、产出、资源变化及增益生命周期须共享一份敌人/角色/队伍/场地状态，随后才能比较完整动作序列的伤害、耗时及SP收支。

重算固定基准：`uv run --locked python -X utf8 scripts/skill-data/compute_fixed_damage_baseline.py`。针对验证：`uv run --locked python -X utf8 -m unittest tests.TestDamageResolution tests.TestTimingDps -v`。输入来自已提交的原生快照及canonical配装/技能文件，不需要客户端解包入口。

本批159项针对验证通过，包括固定属性、技能等级、潜能倍率/增量、消费量、受益对象、类型筛选、到期、同源刷新、独立计时士气、暴击上限、概率事件未触发不施加、循环排序及实际SP/CD等待。全仓907项，剩3个失败和4个错误，名称与此前879项运行一致；这7项此前已在真正PR base `aeee74a4` 中复现。Ruff I/F、JSON/Python解析及差异检查通过；固定面板重算可复现，16角色canonical数据除显式绑定和遗留标记归一外不变，原生成长定义全部保留。

核验应覆盖类型不匹配不加成、支援作用于正确队友、命中时增益过期、条件未满足不生效、智识缩放及上限、同槽天赋低阶不重复叠加、增幅与脆弱分别结算。做到这些后，才能量化低直接伤害的支援战技对后续动作的收益。
