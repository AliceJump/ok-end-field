# 伤害增益接入梳理

本审计针对 PR #436 当前代码与本地数据快照（2026-10-03），说明哪些数值进入了伤害基准、哪些效果尚未进入逐次命中的结算。管理员采用用户指定的 P3；普通六星 P0、四五星 P5、各槽战斗天赋最高阶。潜能与天赋的基准选择不等于它们的全部效果已自动应用。

## 当前覆盖

| 内容 | 当前状态 | 主要缺口 |
| --- | --- | --- |
| 基础攻击、武器攻击、主副能力 | 静态基准已计算 | 通用养成档案尚未统一；余烬有独立80级档案 |
| 武器、装备的常驻攻击与伤害加成 | 已识别的常驻词条参与计算 | 依赖触发条件的词条跳过；不能视为装备全部效果已计算 |
| 各技能实际伤害元素 | 静态基准按技能元素选择对应加成 | 多段、替换攻击需要逐段保留类型 |
| 常驻暴击率、暴击伤害 | 静态期望已计算 | 伊冯等战斗中逐层获得的暴击增益没有逐击结算 |
| 技能给予的元素/法术增幅 | 描述、等级表及效果标记已保存 | 强度、时长、受益对象与独立乘区尚未统一绑定、执行 |
| 敌方脆弱、其他承伤提升 | 效果类型及部分条件已保存 | 没有在每次命中时读取敌人当前承伤效果、匹配伤害类型 |
| 天赋、潜能的攻击提升等效果 | 原生定义、参数与条件树已保存 | 原生 modifier 运算及条件尚未全部映射为可执行伤害修正 |
| 连击、破防、附着与反应 | 有局部状态/规则及保守或满口径估计 | 未与全部技能、增益、持续时间及资源变化串成统一战斗过程 |
| 抗性、防御、失衡窗口、条件装备 | 部分公式在机制文档中 | 当前静态直接伤害为标准假人口径，不能代表具体敌人和实际窗口 |

`compute_damage_baseline.py` 的当前直接伤害主要是攻击力 × 技能倍率 × 已识别伤害加成，再求暴击期望。`skill_rotation.py`、`timing_dps.py` 和阶段规划器读取这些基准或伤害上下界。支援描述匹配只用于保留支援动作，不会为后续攻击自动乘上增幅或脆弱。

已有两个局部 `TeamCombatState`：`combat_model.py` 管理共享连击池，`team_phase_planner.py` 管理阶段、SP、私人资源和状态标记。它们尚未形成统一的敌人、角色、场地、计时增益与逐击伤害状态；不能把已有类名当成完整机制模拟已接入。

## 数据存在但尚未绑定的实例

以下数字取自当前 canonical 技能等级表的最后一列，表示该列的技能口径；不替代后续按实际技能等级取值。

- 安塔尔战技：电磁、灼热脆弱各10%，持续60秒。对应效果仍为 `value=1`、`duration=null`。
- 安塔尔终结技：全队电磁、灼热增幅各20%，持续12秒。对应效果仍为 `value=1`、`duration=null`。
- 艾尔黛拉战技：先消费腐蚀才施加物理与法术脆弱，等级表为20%、30秒；分支中的效果强度、时长尚未绑定。
- 赛希战技：满血治疗触发法术增幅，等级表为15%、25秒，受益者是触发治疗的主控干员。
- 赛希终结技：寒冷、自然增幅基础24%，每点智识额外0.03%，智识部分上限36%，持续12秒。需要读取赛希属性，不能只使用基础24%。

这些效果的 `value=1` 是当前遗留标记，不是100%增益，也不是已解析的真实强度。通用解释器必须先完成绑定；未知数值保持未知。`BUFF_*_UP` 名称也不足以判断属于伤害加成还是增幅，必须结合原生 modifier 与描述分类。

## 结算要区分的层次

1. 力量、智识等主副能力提升先改变角色属性，再影响面板攻击力及读取该属性的天赋/技能。
2. 攻击力提升改变攻击力；元素伤害加成进入对应伤害加成计算。
3. 元素/法术增幅按其实际适用伤害类型作用于输出；与普通装备伤害加成分别记录。
4. 脆弱施加在敌人身上，只影响匹配类型的命中。法术脆弱不覆盖物理伤害。
5. 其他承伤提升、连击、失衡及抗性等分别保留来源与分类，不能把所有百分比相加。具体叠加规则、快照时点与上限按原生数据核验；旧机制文档不能替代当前定义。

## 后续顺序

先把技能等级表和原生参数绑定为明确的修正项：强度/公式、乘区、伤害类型、生效条件、持有者、受益者、时长、叠加与刷新规则。再用统一状态逐次命中读取攻击者增益与敌人承伤效果，随后执行消费、产出、资源变化和到期清理。最后让排轴对比完整动作序列的伤害、耗时及 SP 收支。

核验应覆盖类型不匹配不加成、支援作用于正确队友、命中时增益过期、条件未满足不生效、智识缩放及上限、同槽天赋低阶不重复叠加、增幅与脆弱分别结算。做到这些后，才能量化低直接伤害的支援战技对后续动作的收益。
