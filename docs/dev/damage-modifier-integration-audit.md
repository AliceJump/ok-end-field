# 伤害增益接入梳理

本审计针对 PR #436 当前代码与本地数据快照（2026-10-04），说明哪些数值进入了伤害基准、哪些效果尚未进入逐次命中的结算。管理员采用用户指定的 P3；普通六星 P0、四五星 P5、各槽战斗天赋最高阶。潜能与天赋的基准选择不等于它们的全部效果已自动应用。

## 当前覆盖

| --- | --- | --- |

| 武器、装备的常驻攻击与伤害加成 | 已识别的常驻词条参与计算 | 依赖触发条件的词条跳过；不能视为装备全部效果已计算 |

`compute_fixed_damage_baseline.py` 生成 `fixed_damage_baseline.json`：固定武器、套装、主副能力、属性节点、潜能常驻属性和已核实的黎风常驻攻击天赋先计算完成，保留攻击白值、固定攻击、攻击百分比和属性系数等分量。常驻战技伤害等加成与常驻增幅分开计算；条件武器/套装不提前假设触发。产物不包含拼接的普攻/连携循环，也不默认满连击或私人资源。

`timing_dps.load_damage_quotes()` 默认读取新固定基准；普通战技循环估计调用 `TimedDamageState`，按时序更新明确的基础 cast/hit 生产者，并将增幅、脆弱等收益应用到后续匹配伤害。重复阶段判定包含增益剩余时间，支援动作先为紧随的匹配攻击准备SP/CD，避免增益在等待中耗尽。旧 `damage_baseline.json` 仍供原有 `skill_rotation.py` 和复杂阶段诊断读取，不将旧满口径机械地搬到新固定基准。

估计得到的支援SP门槛及后续CD要求由 `TimedCombatLogic` 执行；后续队友死亡时不以该门槛永久阻塞存活角色。增益在模拟中的生效点仍是时间估计，不表示实战按键成功已经证实每一段命中。

`damage_resolution.py` 支持逐击结算、主控/本人/全队/其他队友/指定敌人、同源刷新、不同来源区分、独立层数计时、暴击上限、非暴击伤害和未知参数反馈。攻击提升作用于攻击白值，固定攻击和已计算的属性系数不重复乘算。缺少强度、时长或属性输入时返回未定价结果，不用零或标记1代替。场地实例记录生产者和消失时点，进入场地的增益截止时间受场地剩余时间限制；离场、提前清理和自然到期都会移除对应实例的增益。

原生逐段命中时间线现在由 `CombatWorldState` 执行；`TimedCombatLogic` 在确认施放后提交预测状态，拒绝/超时则丢弃。已编译的战技替换由就绪状态判断，SP 读取实际 HUD 覆盖预测。动作选择仍沿用旧排序和阶段计划，新序列搜索尚未接管运行排轴；全部被动监听、法术反应、持续效果、场地反馈和条件装备也未完成。详见 [原生动作执行审计](native-combat-execution-audit.md)。

`CombatWorldState` 统一保存敌人、角色、队伍资源、效果、原生 buff、计时器、事件队列和逐击伤害；旧 `combat_model.py` 与 `team_phase_planner.py` 仍分别提供局部规则和旧阶段执行。统一容器存在不等于全部原生动作已可执行或已完整接入优化。

## 诀与提弗洛斯的原生核验

`skill_timings/20261002/ranked_blackboards.json.gz` 已扩充到366项技能的12级参数，包含消耗及冷却。原有诀、提弗洛斯两项曾由两个一致的本地解码表交叉核验；扩充项来自当前 SkillPatchTable，不宣称全部已获得独立第二来源。读取前校验摘要，缺少参数或等级直接报错。753项索引新增效果起始帧摘要，来自已校验的原始时序记录；读取摘要无需提前解压完整记录，原始记录保持不变。

- 诀的固定配装智识 ≥ 意志时为智形态；原生 `CompareDeckAttr` 决定形态。战斗中属性变化不直接切换形态。意形态连携施加脆弱时另通过 `StoreAttributeValue` 读取当时意志，缩放值保存在该次效果中。
- 智形态连携：自然/寒冷脆弱基础4%，持续4秒。意形态：基础4% + min(施加时意志 × 0.0125%, 等级上限)，持续6秒；9级额外上限7.5%、最高级额外上限8%。该系数来自连携等级patch，与终结技天赋的0.02%/12.8%是两套参数。
- 智形态自身战技提前结束囹圄后的脆弱为4%、2秒，与原连携使用同一效果身份进行替换，避免重复相加。再次施加原法术附着只保留在意形态分支。智形态返技力从 `atb_return_wisd` 取值：9级28、最高级30。P1只给意形态脆弱额外6%；已有潜能资源producer另追加10SP，基础返还不重复计入。
- 提弗洛斯箭阵 `persistent_time` 各级为6秒，持续伤害与区域Aura的时间线为180帧（30fps）。Aura将等级patch的自然爆发承伤增量赋给敌方buff；9级8%、最高级10%，不适用于普通自然伤害。buff自身的20秒配置不能作为箭阵实际有效窗口。

共用结算接受实际场地生成、进入、离开与销毁事件；同源同值箭阵重叠只计一次，各实例分别清理。同源不同强度重叠暂返回未定价，待原生优先级规则确认。普通战技循环没有据此虚构连携命中、形态分支或敌人始终在场地内；完整事件生产者与实战反馈仍是下一层工作。

此前全仓916项中的7项回归已处理：测试夹具的缺失方法、角色键名、同一时点读取缓存的预期、SP溢出时其他角色可施放的预期，以及伊冯不匹配元素的附着估计。2026-10-04 在新增角色事件钩子之前，全仓943项全部通过；角色钩子追加验证见原生动作执行审计。

## 数据存在但尚未绑定的实例

以下数字取自当前 canonical 技能等级表的最后一列，表示该列的技能口径；不替代后续按实际技能等级取值。

- 安塔尔战技：电磁、灼热脆弱各10%，持续60秒。对应效果仍为 `value=1`、`duration=null`。
- 安塔尔终结技：全队电磁、灼热增幅各20%，持续12秒。对应效果仍为 `value=1`、`duration=null`。
- 艾尔黛拉战技：先消费腐蚀才施加物理与法术脆弱，等级表为20%、30秒；分支中的效果强度、时长尚未绑定。
- 赛希战技：满血治疗触发法术增幅，等级表为15%、25秒，受益者是触发治疗的主控干员。
- 赛希终结技：寒冷、自然增幅基础24%，每点智识额外0.03%，智识部分上限36%，持续12秒。需要读取赛希属性，不能只使用基础24%。

上面示例记录的是绑定前的缺口。本次通过 `damage_modifier` 中的等级表/最高阶被动参数引用绑定真实值，遗留标记1改为null；`SkillEffect.damage_modifier` 保存有单位和乘区的解析结果。默认与原固定基准一致取最高技能列，也支持显式R9；潜能增量、倍率和持续时间修正按实际选择生效。`BUFF_*_UP` 名称不作为乘区判断依据。

## 结算要区分的层次

1. 力量、智识等主副能力提升先改变角色属性，再影响面板攻击力及读取该属性的天赋/技能。
2. 攻击力提升改变攻击力；元素伤害加成进入对应伤害加成计算。
3. 元素/法术增幅按其实际适用伤害类型作用于输出；与普通装备伤害加成分别记录。
4. 脆弱施加在敌人身上，只影响匹配类型的命中。法术脆弱不覆盖物理伤害。
5. 其他承伤提升、连击、失衡及抗性等分别保留来源与分类，不能把所有百分比相加。具体叠加规则、快照时点与上限按原生数据核验；旧机制文档不能替代当前定义。

## 后续顺序

接下来核对其余天赋与条件武器/套装的原生运算和叠加规则，再将已绑定的事件接到统一动作结果和实际逐段时间线。消费、产出、资源变化及增益生命周期须共享一份敌人/角色/队伍/场地状态，随后才能比较完整动作序列的伤害、耗时及SP收支。

重算固定基准：`uv run --locked python -X utf8 scripts/skill-data/compute_fixed_damage_baseline.py`。针对验证：`uv run --locked python -X utf8 -m unittest tests.TestDamageResolution tests.TestTimingDps -v`。输入来自已提交的原生快照及canonical配装/技能文件，不需要客户端解包入口。

此前159项针对验证通过，包括固定属性、技能等级、潜能倍率/增量、消费量、受益对象、类型筛选、到期、同源刷新、独立计时士气、暴击上限、概率事件未触发不施加、循环排序及实际SP/CD等待。全仓907项，剩3个失败和4个错误，名称与此前879项运行一致；这7项此前已在真正PR base `aeee74a4` 中复现。Ruff I/F、JSON/Python解析及差异检查通过；固定面板重算可复现，16角色canonical数据除显式绑定和遗留标记归一外不变，原生成长定义全部保留。

核验应覆盖类型不匹配不加成、支援作用于正确队友、命中时增益过期、条件未满足不生效、智识缩放及上限、同槽天赋低阶不重复叠加、增幅与脆弱分别结算。做到这些后，才能量化低直接伤害的支援战技对后续动作的收益。
