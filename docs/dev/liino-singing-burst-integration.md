# 梨诺高歌攻击窗口与电队报价（2026-10-19）

梨诺战技原本只沿用倍率行相加的伤害报价，没有将高歌期间的团队攻击提升纳入爆发比较。本批通过已审核的释放规则导出边界补入一条战技增益，现为10角色16条规则。真实 `TimedCombatLogic.step` 会比较先开高歌再输出与直接输出的收益，公共技力和动画仍计成本，不给梨诺固定角色权重。

## 来源与计价

固定来源仍是注册的干净研究提交 `cc9b471b50cdd6bc8b3a148b4eca93deef4efa02`。`reviewed_support_release.py` 核对5份原生记录的完整来源摘要、起手节点、受益对象、属性乘区及共享叠加键，再按选中技能12级读取常量。

| 项目 | 审核结果 |
| --- | --- |
| 基础战技消耗 | 等级表 `costType=1`、25 SP；不把汇总中的“20、8、18”当作公共SP成本 |
| 姿态起点 | `chr_0035_liino_normal_skill` 的第19个时间块，第15帧，创建 `normalskill_music_tag` |
| 持续 | `music_duration=60` 秒；按现有30 FPS名义投影，施放后0.5至60.5秒 |
| 受益对象 | 姿态 `DuringBuffEnable=5` 的非空间团队攻击光环向其他存活队员提供子buff，本人另获独立子buff |
| 属性乘区 | `attributeType=2`、`formulaItem=6`、`modifyAttributeType=0`，读取 `atk_up=0.10000000149011612` |
| 清理与替换 | 父姿态、子buff和同源攻击叠加键关联；沿用现有来源动作/失效来源清理合同 |

攻击提升按 `白攻击×10%` 加入现有总攻击，再换算伤害比例；不会把总伤害直接增加10%，也不会重复计算固定武器、装备和常驻面板属性。它适用于相应队友伤害报价，不只作用于梨诺本人。

新捕获与固定来源的完整记录并不相等：联合类型标签、曲线文件偏移以及移动、投射物、特效、UI字段有新增或变化。逐项比较确认已有业务字段（排除标签编号与字节偏移）一致，本规则使用的起手、攻击属性、光环和叠加字段未变。没有把旧版本原生代码结论或完整生命周期自动推广到当前客户端。

## 实际决策与生命周期

已有规则消费者直接使用新增快照：候选在预测副本中开启窗口，后续队友报价增加；只有沿用现有执行接受路径后才写入真实窗口。专项复现125 SP时先放梨诺25 SP战技、再放佩丽卡100 SP战技；124 SP无法支付这组动作，不假设未来回复来强行选择。预测不会提前写入实际增益。

同一确认不重复叠层；高歌期间排除梨诺自己的战技中止和普攻，队友仍可继续行动。来源下一次被接受的其他动作按现有保守合同结束旧姿态窗口，终结替换战技时不会将两个攻击提升相加。到期或来源槽位失效后清理，其他来源增益保留。没有新增手动中止、场外打断或死亡识别。

25 SP战技沿用已有低消耗动作的失败提示检查和接受口径，不能称为严格技力扣除确认。明确失败反馈不提交窗口；本批不修改HUD阈值、返还时点或通用施放成功检测。

梨诺战技的持续投射物、命中与结束伤害不能当成起手时刻已保证造成的伤害。因此本批将其直接报价由旧17320.2改为0，仅计算已审核的辅助开启价值；旧报价不能通过调用者覆盖值绕回，普通周期统计和防溢出也消费同一份即时口径。完整持续输出仍待后续事件与命中链，零直接报价不表示技能没有伤害。

## 本批边界与验证

测试覆盖真实step选择和后续收益、SP预算不足、0.5秒延迟、60秒到期、白攻击分母、来源失效、重复确认、终结替换及失败不提交。33份面板/配装、已有15条增益规则、其他131份基础报价及庄方宜姿态保持一致，新增1条增益并修正梨诺战技即时计价。

本批新增5项，释放层80项专项通过；合入最新master `fb6fb472e2532b138ff726ae383dfd68bc59fbc4` 后最终全仓1665项（64.434秒）通过。133测试文件/16职责组登记、Ruff I/F、AST、diff-check及三份产物逐字节重导出通过。原31份补丁重放后仅一处导入附近的上下文变化，无功能补丁丢失。

庄方宜仍缺从实际生成、到达、范围计数到施放快照的完整剑数输入；艾维文娜仍缺有效普通/强雷枪数量和回收路径命中输入。白圈不是精确计数，不把首次免费三位置请求当作已建立三剑，不以最大九剑或固定三枪补全收益。汇总中的伤害估值也不能替代当前固定配装报价。当前三位输出基础战技为100 SP，梨诺为25 SP，庄方宜首次免费战技按既有合同为0 SP。

未做游戏现场复测；本批不宣称四人电队全部机制或整个机制系统完成。PR #489继续按用户要求暂不合并。
