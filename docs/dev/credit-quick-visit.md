# 收信用任务：快速拜访与结束判定

`CreditCollectTask` 首次从好友列表进入，后续优先使用游戏的“快速拜访下位”入口。到达后仍通过访客终端完成情报交流和生产助力。

## 次数与完成条件

游戏把以下情况都显示为“暂无下位可拜访”：

- 自己当天的情报交流和生产助力剩余次数都为零。
- 自己仍有次数，但筛选不到其他满足条件的好友。

因此仅看到空状态、按钮消失或 OCR 找不到按钮，不能证明当天次数已用完。任务从好友列表右上角、访客终端左下角读取游戏显示的两项 `剩余/上限`；**两项剩余都明确为零才返回完成**。首次运行时如果列表显示两项均为零，无需再进入好友船。

取消原先固定从 5 次开始递减的估计。每次进入终端先读取实际次数，操作后等待界面同步，只有观测到剩余减少才计入本次 `exchange_time`、`help_time`。因此当天已经手动做过一部分、按钮点击未生效、某位好友没有交流入口，都不会虚增完成数或把尚有的交流次数清零。

OCR 对不完整、超出上限或存在多余分数的结果返回未知；未知不等于零。终端计数无法识别时停止本次流程，保留此前已经确认的统计。计数变化需持续可读 0.5 秒；不将次数回升作为操作成功。

## 正常流程

1. 沿用采购中心领取信用的入口。
2. 打开好友列表，读取剩余次数。先找可交流图标，未找到再找可助力图标；次数为零的项目不再搜索。
3. 进入好友船后打开访客终端，读取次数，先交流再助力。
4. 关闭终端，确认回到好友船 HUD。
5. 剩余均为零则结束；否则等待“快速拜访下位”或“暂无下位可拜访”状态，最多 10 秒。
6. 快速入口可用时按 Tab。先确认旧船 HUD 消失，再等待好友船 HUD 出现，避免把旧船误当成已经到达下一位。

快速入口的匹配文本来自当前游戏简体、繁体语言表，位于 `assets/lang/credit_collect.json`。由于用户提供的是按钮局部截图，识别范围采用屏幕上半部，不根据局部截图猜测按钮的绝对横坐标。

## 生产助力配置

保留持久化配置 `尝试仅收培育室`，不新增开关、不迁移账号设置。

- 开启：沿用原有右滚到舱室列表末端、优先最右可助力项的策略，每位好友尝试一次。末端没有可助力项时回到左侧，尝试其他舱室。
- 关闭：可连续助力，每次点击后重新识别按钮并等待次数减少，避免继续点击已失效的位置；每位好友最多尝试 5 次。

这仍是原有界面位置偏好，不把游戏快速选人误称为“优先选择有培养舱的好友”。

## 兜底与停止

- 快速入口不存在、显示暂无目标或未确认完成跳转：本轮关闭快速路径，回好友列表补查。
- 连续两次拜访没有确认任何次数减少：关闭快速路径，改用列表补查；补查后仍无进展则停止，返回未完成。
- 列表补查时，仍先交流后助力。每类最多检查首页加 7 次下滚，切换类别时先滚回顶部。拜访中的当前好友置顶，首页扫描跳过该行。
- 尚有次数却查不到候选：日志明确记录“未确认全部完成”，返回未完成。
- 全流程最多处理 15 位，避免游戏兜底反复选择已经助力过的好友。
- 无论成功还是中止，均写入已经确认的交流、助力次数。

## 验证范围

自动测试覆盖次数解析、当天部分完成、入口消失后的列表补查、无收益停止、助力失败不计数、培养舱偏好、重复刷新按钮，以及旧 HUD 不能作为快速跳转成功等分支。

已使用仓库原有好友列表和访客终端截图，在 1920、2560、3840 宽度下离线执行当前 OCR 模型；列表两项分开裁切，避免在 2K/4K 下合并成 `4/55/5`。用户提供的“快速拜访下位”截图也已核验 OCR 文本。研究脚本、日志和解包原件保留在主仓 Git 忽略目录 `tmp/friend-quick-visit-research-20261017/`。
