# 技能时间排轴的 DPS 搜索实验

本模式建立在预生成技能时间数据与旧战斗模式之上。本版在「技能时间排轴」内复用原伤害按钮的 `damage_baseline.json` 明细，新增可重复战技循环搜索。仍默认关闭，开启方式见 [时间模式说明](skill-timing-mode.md)。旧「伤害优先排序」开关继续控制旧模式；独立时间模式直接使用本版评分，不再受旧策略开关控制。

## 伤害分子

原按钮按 `cycle_expect` 排序，其中已经包含战技、一次连携和两次普攻。用这个数除以战技时间会重复计算连携和普攻。本版分别读取每种技能的 `full_expect` / `crit_expect` / `non_crit`，循环搜索仅使用战技伤害。已有 `full_caliber_requires` 和保守口径继续参与：需要附着时，消费者只有在本模型中获得尚未过期的附着才按满口径计分，否则按保守口径计分。消费者消耗附着，异元素施加会清空旧附着，不把一次喂养重复算给所有后续技能。

不因为队伍里有连击施加者，就把所有战技乘满连击加成：连击是消耗型共享资源，当前监测未提供层数或触发证据。支持型战技中已知有增幅、脆弱、易伤、连击或回复技力文案的角色保留在候选循环中，但没有额外编造增伤倍率。这个保留是保守策略，不能证明这些技能必须每轮使用。

## 循环时间分母

对四个战技搜索最多 64 种有序子集，允许省略低收益战技；同一个战技在候选内最多一次，候选重复执行即可形成单角色或多角色循环。搜索范围没有包含任意重复次数、完整状态机或所有动作组合，所以它求的是该候选集合中的最佳预计战技增量 DPS。

每个候选从 300 SP 开始模拟，保留 300 上限、CD 和上一技能保护时间。模拟重复循环，直到首个战技出手时的 SP、剩余 CD 和附着状态重复；**下一次首个战技的开始时间减去本次开始时间**才是完整可重复窗口。开局多出的资源只计入单独的开局阶段，不能改善稳定期分数。最多尝试 64 轮，未形成稳定周期就拒绝该候选，不靠任意的 10/20/60 秒截断窗口评比。

- 技力恢复采用仓库已有的名义 8 SP/s，模拟期间自然恢复与 CD/施法等待共享时间，不能把三者简单相加。
- 原生等级补丁的实际费用与 HUD 门槛分开：梨诺启动费用是 25 SP，监测仍需要至少一整格才能可靠出手；不能为了整格检测把每次实际消耗改成 100 SP。
- 规划器使用与执行器一致的 `actionable`：`exclusiveFrame` 是硬锁，匹配的 `AllowNextSkillAction` 可在硬锁后直接接续；无匹配白名单时使用 `min(duration, max(0.3, exclusive) + 0.15s)` 兜底，而不是把完整 `duration` 当输入锁。管理员仍取候选 profile 的保守上限。
- 附着按名义 20 秒处理，并暂在技能保护结束时计入。实际命中时刻尚未校准，附着是否命中、增伤是否触发、持续费用、攻速、时停和技能强化态仍有不确定性。
- 不支持的多段角色、缺少伤害/费用或无有效收益时，回退已有伤害顺序及安全时间保护。

## 执行与观测

技力条、队伍识别、终结技、连携和退出检测仍由现有监测逻辑决定。预测的技能时间/CD、SP 或伤害不能代替屏幕就绪条件。战技费用确认失败时留在原位置，既不推进循环，也不记录完成轮数。

终结技不加入“每轮必然可用”的长期分子；实时就绪后，按各自伤害/保护时长给同时就绪的终结技排序，未知支援收益仍允许释放。连携不知道属于哪位角色，继续按原就绪检测处理；估算伤害只取队内候选的最低值，绝不将四人的连携都加到一次按键上。

运行中以确认消耗的循环首战技为边界，记录最近五轮窗口。窗口包括中途终结技、连携、技力等待和按键重试占用的时间。日志输出：

```text
时间排轴DPS规划: 战技 [...], 可重复窗口 ...s, 预计战技伤害 ..., 战技增量DPS ...
时间排轴DPS观测: 最近 N 轮平均窗口 ...s, 基准技能DPS估计 ...（窗口实测，伤害未实测）
```

实测窗口与基准技能伤害估计分开报告。观测分子包含模型战技收益，以及本轮尝试释放的已知终结技/连携收益；首轮用开局口径，后续用稳定期口径。没有 OCR 验证真实伤害，不能把该估计称为实际队伍总 DPS。普通攻击、反应/DoT、实际配装、敌人抗性、支援增伤和敌人状态没有完整计价，完整效果模拟与实战标定仍需要继续做。

## 离线比较

```powershell
uv run --locked python -X utf8 scripts/skill-data/plan_timing_dps.py 佩丽卡 狼卫 陈千语 管理员
# 改变名义恢复率，检查结论对假设的敏感性
uv run --locked python -X utf8 scripts/skill-data/plan_timing_dps.py 佩丽卡 狼卫 陈千语 管理员 --regen 6
uv run --locked python -X utf8 -m unittest tests.TestTimingDps tests.TestSkillTiming -v
```

模型结果不在文档中固化：`actionable` 规则改变后，旧的完整窗口数字已经失效。请直接运行脚本得到当前分支结果，并用实战日志中的“时间排轴DPS观测”核对。即使同一模型下分数提高，也**不能视为实战提升结论**；满配伤害基准中的条件倍率和部分前置状态仍未全部转为运行时条件。
