# 固定配装定稿（2026-10-07）

定稿四件写在 `scripts/skill-data/generate_character_builds.py` 的 `CURATED_BUILDS`，由生成器写入 `assets/data/character_builds/*.json`，再重算 damage_baseline.json（固定面板在另一分支另行重算）。

## 1. 规则

- 每名干员固定 4 件：护甲 1、护手 1、配件 2。同名配件可以装两件（如险关通信器×2）。
- 至少 3 件属于同一个有套装效果的套组；纾难、涉渊等“无套组技能”的套组不计。
- 第 4 件为自由件，按干员特性选择。
- 生成器校验：件名存在于 `equipments.json`、部位顺序为护甲/护手/配件/配件、存在 3 件同套。

## 2. 旧数据的问题

- 旧解析器只保留装备页推荐卡中的 `recommended_operator_ids`，随后再按“哪些装备推荐这个干员”反查拼件；这个中间表示会丢掉槽位顺序与重复数量，所以双配件会被压成一个不同装备，出现大量“只有 3 件”的假象。
- 2026-10-07 用森空岛 `/web/v1/wiki/item/info` 原始响应复核险关手甲（itemId `2335`）：同一张“推荐装备干员”卡已经完整包含提弗洛斯（`2116`）的护甲 `2334`、护手 `2335`、配件Ⅰ `2336`、配件Ⅱ `2336`。即官方源能直接表达险关通信器 ×2，不需要从多个装备页推断第四件。
- 因此“反查只有 3 件”是本仓库解析/建模丢字段，不代表官方只推荐 3 件。修复后的 `build_loadout_data.py` 会保留完整四槽 `recommended_loadouts`；`generate_character_builds.py` 对同一干员命中第一张完整卡后直接使用，不再重复从其他装备页拼装。
- 新套装（如险关）曾经没有回填推荐干员，且旧标签树缺套装名，`equipments.json` 里险关的 `set` 为空。
- 部分旧反查结果与当前版本脱节，例如萤石、提弗洛斯的自由件是寒冷电磁加成，萤石的拓荒供氧栓是意志/物理件。

## 3. 证据优先级

1. 社区共识充分（EndSync 汇总中主流套装至少 3 套、完全相同四件至少 2 套）：采用社区主推四件。
2. 社区样本不足：取两个以上独立来源（EndSync、GameKee、TapTap、mrfzzmd、ldcapple 等）的共同核心件。
3. 仍无共识：保留官方推荐件，用同套配件补齐第 4 件。

EndSync 页面：`https://endsync.vercel.app/zh/wiki/<slug>/`。“A/B”表示该套装出现在 B 套配装中的 A 套。

## 5. 祀的初始支援配置（2026-10-15）

祀已上线，[官方干员页](https://wiki.skland.com/endfield/detail?mainTypeId=1&subTypeId=1&gameEntryId=2338)的四项技能、RANK1–9/专精1–3、1–90级基础属性和两项战斗天赋已收录。
武器首选按官方推荐顺序取「玉中身」，同页备选为「悠久传承」「赫拉芬格」；两把新武器已补齐90级攻击、Rank1–9技能及推荐基质「无瑕基质·效益」。

四件采用本机客户端 `CharPresetTable.std_90_chr_0036_jsspsi`：**50式应龙软甲 / 50式应龙手套 / 50式应龙信标 / 纾难印章**。该预设是90级、零潜、四技能12级，装备配置可直接核验（evidence_level=1，官方客户端标准预设）。它与干员装备界面“推荐”入口的对应关系尚未证实，不能称为该页面的推荐配装，也不代表社区毕业共识。

本机Table索引更新于2026-10-15 07:55:45，包含祀 `chr_0036_jsspsi`。这证明本机已安装该次热更新，不代表已经对照服务器最新版本。复查时Wiki装备目录258件，本机EquipTable为276件，三件新应龙装备只在本机表中找到；[EndSync](https://endsync.vercel.app/zh/wiki/si/)暂无祀的精选配置。

所需三件新装备的名字、部位、套装、基础与精锻3词条来自 `ItemTable`、`EquipTable`、`EquipSuitTable`、`I18nTextTable_CN`；套组攻击15%和条件连携20%/最多3层由 `SkillPatchTable.passive_equipsuit_atk_02` 交叉核验。生产所需的最小数据在 `assets/data/client_loadout_data.json`，Wiki生成器保留客户端补充，后续Wiki收录同名条目时以Wiki条目替换；原生ID与Wiki itemId分别存储。

静态基准统一为90级、专精3、武器Rank9、装备精锻3（不沿用预设武器基质的具体蚀刻）：攻击6060.6、智识628、力量274、终结技充能效率加成33.4%、装备连携技伤害加成125.6%；直接倍率为战技100%、连携750%、终结技500%。
伤害记录13%按已结算伤害计价，笔意结束或收笔造成固定伤害，不作为额外13%攻击倍率；笔意爆发5点失衡另行结算。连携每层额外100%需要消费/吸收事件与层数，上述750%只代表基础段。
专武定身后的易伤/连携强化、终结技增幅、应龙之锐与天赋减冷却/加速均依赖战斗状态，不计入无条件固定面板。

计算器同时补齐了武器「主能力+X%」词条解析，悠久传承Rank9的19.6%仅乘主能力，不乘副能力；相同修正也回填了梨诺「曜夜的首演」漏计主能力词条的静态基准。

玉中身Rank3「寒冷伤害提升·大」的Wiki原文为14.9%，客户端 `WeaponBasicTable` 确认其与悠久传承共用 `wpn_sp_attr_crystdam_high`，`SkillPatchTable` 的level=3值为 `0.14444445073604584`，因此显示值按14.4%收录。修正及来源保存在客户端补充文件，Wiki重新导入时仅修正该物品、等级与词条；Rank9基准不受影响。

机制语义层保留河山共影100SP→起墨15SP→收笔0SP、20秒笔意与墨魂传递/同次命中去重规则，以及01号位决定寒冷/灼热附着的分支。
目前收录的是静态基准与机制语义；墨魂记录/转移和队伍事件尚未接入完整时间轴伤害结算，不能把标准循环估值当作祀的实际队伍收益。

原始抓取和文件校验哈希保存在主仓库忽略目录 `tools/wiki_catalog/`，不随PR发布。
