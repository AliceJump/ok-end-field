副本移除诊断仅用于揭示下一层门槛，所得部分伤害不能作为推荐或收益比较。没有在正式模型中清除未知项。

四人队的3条目录诊断来自：

- 余烬连携：`CheckDamageDecorateMask+Data`。
- 卡缪连携：两条`CheckBuffIdInContextAdvanced+Data`。

这些来源在`bind_character_events`注册时进入目录诊断，并先于战技搜索触发全队回退。它们可能影响连携触发及后续状态，不能仅因来源是连携就删除。

## 共同根因

### 1. 完整性诊断没有足够的作用域和数据依赖信息

[`recommend_battle`](../../src/data/combat_runtime.py)先拒绝任意目录/世界诊断，再检查所有活着角色的全部战技变体和嵌套回调，包括当前不可用的分支。安全性有保守边界，但没有解释“这个未知会影响哪项比较”。因此不断补独立节点，未必移除真实队伍的最后一个阻塞。

需要给诊断保存角色、Skill、生产事件、读写状态、控制流/目标影响和分支前提；由候选动作及后续依赖决定是否必须拒绝。结构加载失败、无法界定写集合、真实控制流未知继续拒绝。未观测动作已污染共享状态时，也不能简单换成只检查当前战技。

### 2. 有资源结构，但缺少执行上下文生产者

曲线已能解码，却没有Unity求值和消费者合同；buff已能挂接，却没有真实CastEnd原因、目标Skill对象及Disable生产链。调用接口被单测覆盖，不会自动产生这些事件。[`native_skill_runtime`](../../src/data/native_skill_runtime.py)明确要求确认的结束输入，目前CombatRuntime和TimedCombatLogic没有调用这条结束接口。

主控角色已存在于世界，但带过滤条件的mainchar/pos目标组尚未绑定；“单敌在范围内”不能证明每个距离、角度、过滤条件成立。输入缓存、Jump和Interrupt也会影响动作选择或后续事件，不能按表现节点忽略。

### 3. 识别输入不足，而且缺口目前持续锁住推荐

[`TimedCombatLogic`](../../src/tasks/onetime/TimedCombatLogic.py)在连携成功但不知角色/阶段时记录`Link actor/phase not observed`，目标丢失也记录缺口。[`CombatRuntime`](../../src/data/combat_runtime.py)只增加`observation_gaps`，正常观测中没有恢复路径；同一runtime内后续SP采样不会清除它。

目录只构建战技/连携/终结技，普攻虽在外层持续输入，却没有逐击确认接入这套世界。缺少普攻触发、连携、目标连续性等事实，无法保证破防和天赋状态持续可信。完整模拟之后仍需要“可证明恢复的状态快照或新战斗边界”，不能任意清空gap。

### 4. 搜索尚不足以回答原始收益问题

[`plan_action_sequence`](../../src/data/combat_simulation.py)用累计伤害比较，在伤害相同时比较耗时和末端SP。资源/解锁价值只会通过后续合法动作实现；运行时只搜2步/6秒战技，不包括连携、终结技和普攻策略，末端buff/能量/破防价值未计价。跨三个动作才兑现的收益可能被截断。

另外，搜索允许等待，推荐入口随后拒绝需要等待的首动作。最优等待方案被拒绝时，当前没有再次寻找次优的立即可执行方案。后续需要显式比较“现在施放”和“继续普攻/等待”，不能仅扩大深度。

fork已到约0.4ms，无须继续按旧54ms瓶颈排序；目前未知提前拒绝的搜索计时不能代表完整工作负载。在线宏模型、状态键成本和长窗口参考策略仍待验证。

### 5. 旧计划指标过期，促使续作偏向补节点

旧路线把未复现的9/111和早期54ms作为现状，又将ComboCache等列为场景无关项；后续审计已经否定这种整体放行。阶段接口、解码和节点分类均有价值，但尚未连接成可验收的真实队伍链。更新计划要同时记录启动、动作、动态执行、观测、搜索、现场六层结果。

## 接下来的顺序和验收

| 顺序 | 要完成的工作 | 必须给出的证据 |
| --- | --- | --- |
| A：诊断与依赖 | 将四人队未知定位到生产者/消费者、目标组和回调；区分结构失败、状态污染、当前可达缺口、已证明仅表现的输出 | 固定开场及有破防/追猎/弭弗替换状态的回放；每项保留或排除都附依赖依据，排除不改变目标量；不凭节点名删除未知 |
| B：四人队动作闭环 | 优先补共享主控/目标合同、ComboCache到输入/选技窗口的联系、决定命中/合法性的控制流；随后补弭弗真实换段/结束、骏卫破防事件、余烬庇护参数与监听、卡缪投射物/追猎链 | 基础战技和可达替换、必要天赋/被动/连携回调在同一持续世界严格回放；伤害、SP/能量、破防、buff寿命逐项可核对；禁止靠未绑定分支的部分伤害获胜 |
| C：连续观测（当前后置） | 识别类缺口只登记；有原生证据的模型内事件生产/分派仍属于B的数据执行范围 | 当前不实施画面识别、动作身份检测、HUD阈值或gap恢复；以显式输入的离线事件轨迹检验数据规则 |
| D：收益和预算 | 用可信离线长序列核准短窗口/宏模型；加入等待与立即动作的比较、末端资源和解锁价值 | 回答余烬100SP在不同破防与后续技能条件下值不值得；与长窗口参考一致；完整可计价负载验证25ms预算，不能拿提前失败耗时验收 |
| E：推广与现场 | 复用合同逐角色补全部技能/满级天赋/约定潜能、增幅/脆弱、异常、投射物/场地；验证至少两队 | 逐角色缺口台账、不同机制队伍连续回放、至少两队现场预测/确认/降级对照；重大未闭环项清零才完成整个任务 |

B不要求先把225个Curve节点全部求值：先核实本队曲线的所有消费者；只流向表现且不改变控制条件的输出可在已声明场景内证明排除，进入伤害/资源/选技的曲线必须执行。相同原则适用于位置和控制流，不能按某一示例推广为全局忽略。

A、B以单个共享合同或单角色完整依赖链阶段提交；C、D完成后才能宣称持续接管。第一队是中间验收点，E保留全角色最终范围。固定属性/装备先进入面板，六星默认零潜、主角按约定可达进度、其他星级满潜，天赋满级；余烬80级/技能9级/推荐五星武器基准不变。技力返还时机与HUD阈值继续后置。
