## 相连特效与压力场景

首个发现列可能穿过与血条相连的竖向粉色条。原 PR 用该列的完整高度计算宽度门槛，会漏掉 50x5 的有效血条；更新后最多检查同一水平段的首、中、末三列。既有的 64 行发现预算和 16 行几何预算仍有效。

| 合成场景 | PR 前（ms） | 原 PR（ms） | 更新后（ms） | 识别结果说明 |
|---|---:|---:|---:|---|
| connected_bar_1080p | 0.498 | 0.518 | 0.427 | 原 PR 漏检，更新后恢复有效血条 |
| connected_bar_2160p | 1.058 | 1.164 | 0.917 | 原 PR 漏检，更新后恢复有效血条 |
| thin_rows | 0.573 | 2.094 | 1.953 | 三者均能发现噪声之后的有效血条 |
| tall_narrow | 0.647 | 2.173 | 2.140 | 三者均能发现竖条之后的有效血条 |
| solid_block | 1.170 | 3.000 | 1.429 | PR 前误收宽 100/高 30 色块，两个 PR 版本均拒绝 |
| residual_context | 0.674 | 1.358 | 1.169 | PR 前漏掉 8x4 残血，两个 PR 版本均结合槽线检出 |
| middle_band_no_context | 0.677 | 1.097 | 0.991 | PR 前直接接受 49x5 无槽线色块，两个 PR 版本均拒绝 |

合成场景不计入上面的 174 张实图汇总。合成场景的不同版本可能走向不同判定分支，需结合结果说明解读耗时。

薄噪声行和高窄竖条压力场景仍明显慢于 PR 前：更低的发现宽度门槛会检查原本直接过滤掉的噪声。这是更完整候选搜索的成本，扫描仍受两种行预算约束；不能把实图均值的下降推广到所有噪声分布。

为控制代表列检查的开销，扫描直接从腐蚀掩码获取有候选的行及列，避免生成、重复筛选和排序全量坐标；同一次 ROI 扫描对相同框只执行一次失败上下文检查。缓存不跨调用，重复出现的合格行仍计入几何预算。

## 计时方法与复现

- Python 3.12.14，OpenCV 4.12.0，NumPy 2.2.6，OpenCV 固定单线程。
- 每张图先解码，逐版本预热 12 次；每个版本、每张图、每种模式各运行 7 组，每组 50 次，版本顺序轮换。
- 首次扫描计时包含重置探测状态后的一次真实 `probe_enemy_presence_fast()` 调用；持续探测计时保留预热后的缓存分片/无敌人确认状态。
- 每张图取 7 组平均调用耗时的中位数，再对图片等权汇总。表中 P95 是逐图中位耗时的第 95 百分位。
- 图片解码、用于比较命中框的全区域扫描、游戏抓帧、叠层和调试帧写盘均不计时。
- PR 前源码取 `c0998d7affc7310f37b8be12104c27c64447c571`；原 PR 取 `32f123d418424bc5f30495564ac01142f831eb99`；更新后测量的是工作树中的源码，SHA-256 为 `160ab5fc1c4ad9ffe1c99e1c8cedede598183b97a53b8ec0428df0271caecca1`。

```powershell
uv run --locked python -X utf8 scripts/testing/benchmark_enemy_health_probe.py --templates D:/items/project/github_project/ok-end-field/ok_templates --include-untracked --baseline c0998d7affc7310f37b8be12104c27c64447c571 --incoming 32f123d418424bc5f30495564ac01142f831eb99 --iterations 50 --repeats 7 --output tmp/pr481/final-benchmark.json
```

`--templates` 可指定另一个素材仓目录，默认使用当前工作树的 `ok_templates`。不加 `--include-untracked` 时只使用素材仓已入库图片；复现同一组 174 张图还需本机的 24 张补充截图。
