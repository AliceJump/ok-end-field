# 导航对中与上下文学习

Issue #543 的运动模型与学习权限独立。`NavigationMixin.align_ocr_or_find_target_to_center()` 的
`move_profile` 描述目标坐标语义：`hud_direction` 使用椭圆归一化、中心减速与外圈加速；
`world_projection` 使用普通屏幕投影对中。

当前导航 Feature 默认为 HUD，OCR 默认为世界投影；方向型 OCR 需显式指定 HUD。
YOLO 始终使用普通对中，角色名字 OCR 显式使用世界投影。`navigate_until_target()` 可通过
`nav_move_profile` 透传给途中实时修正。OCR 专用检测/移动 callbacks 保持原适用范围。

两种 mover 的计算位于 `src/interaction/target_movement.py`；滑索保留自己的 geometry 参数。
实际鼠标发送经过任务实例，激活被拒绝时不报告已接受的位移。目标短暂丢失时仍使用同一
运动模型及轴约束，但旧框不能成为成功证据。实际成功仍由当前帧检测与原导航状态机验证。

战后 HUD 方向标也使用椭圆；战后 YOLO 使用普通对中。运动 profile 不代表允许读取或写入
学习经验。本次运动模型改造没有扩展经验缓存的适用场景。

## 学习内核与权限边界

`src/core/learning/` 不依赖 Task、Qt 或识别器。`WorkflowContext` 使用流程、阶段、大区/
小区、入口锚点、canonical target ID、入站路线、捕获/相机 profile 和可选起始 yaw 建立
版本化身份。`RouteContext` 同时提供完整 private key 与包含当前段目标的 prefix key；
未知 family 只有 private key。路径查询和迁移的数据层见下文，业务接入范围见“实际接入与实测”。

`LearningRecord` 将动作统计与归一化 `TargetPrior` 分开。动作采用可合并 Welford 均值/M2，
样本不足时不提供方差估计。legacy 数据的方差标为 unknown，不按零方差使用；开始收集
新样本时保留 legacy 数量，单独建立可验证的新统计。high/medium 复用还需至少三个已验证
低方差样本且无连续失败；medium 动作减半，low 仅提供目标提示，invalid 不读取先验。

`LearningStore` 使用独立 schema v1、内存索引、同进程锁、唯一临时文件及原子替换。
写失败不提交内存状态，损坏条目跳过，超限按更新时间淘汰。多个同进程实例会刷新文件变化，
更新操作串行化；此格式不承诺多进程并发合并。默认路径为忽略目录
`tmp/context_learning_cache.json`，不改变用户任务配置。
同一规范化路径还维护进程内写入代数，成功 replace 后才递增，保证时间戳与大小相同的替换
也会使其他实例的缓存失效。只有确认文件不存在时才从空记录初始化；未知 schema、读取或
stat 失败时保留原文件、禁止覆盖，下次访问重新尝试。合法 schema 内的损坏条目仍逐条跳过。

`create_learning_session()` 是初始对中会话入口，支持 workflow 与 route。输入及证据使用同一 active clock 域的时间，按
接受的输入记录包含 replay 与 correction 的总量，并提供输入前的单调 frame ID。取得
输入后的真实新帧对中证据，即通过 `confirm_alignment()` 提交样本并结束会话，不等待到达。
学习只覆盖 Initial Align，后续 `navigate_until_target()` 不接收学习会话、不读写持久动作先验，
导航动作或到达失败不反向修改已经自验证成功的对中样本。一个会话只能领取一次 Action Prior。
`confirm_alignment()`/`fail()`/`close()` 均为终态；异常和停止时调用者应
在 finally 中 close，未确认的样本不会自动写入。搜索、额外步行和不完整输入污染本次
动作样本，可信度只降不升。profile 的轴约束同样约束 replay 与记录。

`deny_learning()` 为嵌套、执行上下文局部的禁止作用域。普通内层入口不能解除父级禁止；
退出或停止会恢复权限，但此前 pending 会话永久失效。原 motion/yaw 缓存也在读写入口
执行这一保护。战斗主入口、触发任务确认进入战斗后的逻辑及战后原地寻路既不读取
历史动作，也不 replay 或写样本；手动传入的 initial_move 同样无效。淤积点 F8 恢复链在
实际传送成功、落地稳定后可重新建立与战前相同的入口，详见后文；仅替换 post_battle /
post_battle_retry 禁止状态，不解除 battle 或其它父级禁止。实时 ellipse/normal
与实时 yaw 校准仍可运行。`battle`/`post_battle*` 流程身份自身也拒绝创建学习会话。
未检测到战斗的普通触发轮询不改变学习 epoch，不会让正常导航会话无故失效。

滑索每段首次对中、送货取货/交付路线末端首次蓝点对中以及淤积点战前首次 HUD 对中已接入。
卖货、联络和演算的流程学习仍待后续接入；不将离线测试视为已经通过游戏实测。

## 路径前缀共享与迁移

`RouteLearning.lookup(context)` 先查完整 private，再查同 family/prefix/profile/yaw 的共享池。
没有目标框、ROI 或检测结果也能返回历史动作；high/medium 的可靠性规则与流程内核相同。
共享池从各来源路线的独立统计临时计算，不把聚合结果再写回来源。重复查询不会重复计数。
只有共同前缀可以共享，分叉后即使距离再次相同也不重合。family 是大区、小区、物理起点、
行进方向、路线类型；捕获尺寸、相机策略、运动版本、轴和起始朝向还须精确匹配。

明显冲突的新来源留下与该共享身份绑定的拒用标记，退出共享并继续收集 private；即使它的
private 暂不足三个样本，也不能重新套用被拒绝的共享模型。private 达到资格后可独立复用。
已有来源互相冲突时不聚合成零位移。未知方差的旧估计与新验证统计分开；有干净新来源时，
旧估计不参与强动作统计。阈值为保守初始策略，尚未经过游戏现场定标。

`nearest_yaw()` 只给出候选朝向。调用者必须实际转向、读取真实朝向，再用实际 bucket
调用 `lookup()`；该方法不会自行移动或把请求的朝向当作校准成功。拒用共享的路线不能借
另一个朝向绕过隔离。共享池每次查询按更新时间最多使用 32 个来源；写入时默认保留 128 条
完整配置路线，连同其各段/朝向记录一起淘汰，整体仍受 store 的 4096 条限额约束。

`src/data/navigation_contexts.py` 根据 canonical 送货目标反查小区域，但要求调用者明确提供
已经验证的入口锚点。配送出站架与传送后去接单的架子分开，未知入口、淤积点和歧义名称
维持 private。配置键相同或距离相同都不能证明物理入口稳定。

`migrate_zip_line_cache(path, store)` 原子导入 v4 快照，原文件保留；导入标记与全部来源在
同一次 replace 中保存，随后从磁盘复读核验。失败不报告完成，重试不重复计数，已有新样本
不被旧数据覆盖。无法容纳完整导入时不落盘。合法源数据中的坏条目单独跳过。
旧样本次数只用于加权旧均值估计：v4 超过 20 次后为 EMA，不能视为原始样本的精确总体均值。
旧方差标为 unknown；新成功样本另起统计，并保留 legacy 数量。v3 校准后的 suffix 单独
使用 `legacy-v3-suffix` 运动版本，不与 v4 完整动作混合。

旧文件没有滚轮/相机 profile，默认导入 `legacy-unknown`，保持 private。只有调用者提供
可靠的 profile resolver，才允许 v4 进入已知 profile；family resolver 还须另外确认物理
起点。迁移不能改变捕获尺寸。生产滑索首次进入学习时会尝试迁移，失败时可继续视觉闭环并在
下次重试；已经完成的迁移不重复累计。生产路线不再读取或写入旧 v4 motion API；旧文件保留。

## 实际接入与实测

`navigation_learning.initial_alignment()` 只包围一次 Initial Align，记录任务实例实际接受的
鼠标输入。`align_initial_target()` 在目标识别前领取至多一次历史动作，再进入原对中循环。
OCR/Feature/YOLO 检测后的居中分支提供真实新帧证据；短时旧框不能提交样本。输入、证据和
超时使用 active clock，持久化的更新时间使用 wall clock，避免重启后按系统运行时长错误淘汰。
滚动、额外按键/步行、点击、搜索、捕获尺寸变化、嵌套对中、拒绝或部分输入都会污染当前样本；
停止时只关闭会话并恢复实例方法。受污染的执行也不处罚原本正常的历史动作。

滑索的入口 profile 明确区分滚轮最大视角与未滚动；开启滚轮时在原始 yaw 采样前统一调整一次，
学习对中循环不再重复滚动。最近 yaw 校准、历史重放和微调的累计量一起记在原始 yaw 下，校准
失败/重放未稳定则只执行视觉闭环，不写新动作。已验证零动作时不为借用其他朝向经验而额外转向。
首次对中返回前已经自验证并提交，此后的金色门重试、激活、滑行和到达不读写该会话。

送货把 canonical NPC/小区域、实际入口、完整入站路线和捕获 profile 传到末端第一次蓝点
对中。只有当前大区/小区域已明确匹配，才附加已知路线 family；不根据目的地填补未知当前位置。
末端下架后寻找登架按钮，再执行 V 追踪和重新登架，以重新登架后的状态作为该入口的学习起点。
寻找按钮期间可以 WASD 踱步，这些动作发生在新会话开始前，不会污染重新登架后的蓝点样本。
未经过重新登架的路径不套用该入口经验。起始 yaw 不能可靠读取时只允许 medium 部分动作。
后续 `to_end_and_submit()` 等处保留原来的实时校正，不传 session，不重复重放；导航失败
不会反向处罚已经保存的初始化样本。

实测须运行包含本次接入代码的版本，保持分辨率、灵敏度及视角设置一致：

1. 在送货任务中选择同一路线重复执行。前三个干净成功样本用于训练，期间采用视觉对中；
   `完整循环测试` 留在滑索上，可验证各 NPC 路线的段级学习和同前缀共享，不包含末端蓝点学习。
2. 从第四个相同入口开始，观察日志 `[initial-align-learning] replay` 是否先于目标检测发生，
   随后出现 `verified ... saved=True`。样本不足、有较大波动或不匹配时不会强行重放。
3. 使用正常送货流程验证 pickup/dropoff 蓝点入口；即使随后导航失败，已经出现的
   `saved=True` 样本应保持不变。重新登架前的踱步不影响本次学习；若学习开始后又额外走动、
   搜索或发生输入异常，允许继续流程，但不保存当前样本。保存后的导航恢复不影响已提交样本。
4. 检查 `tmp/context_learning_cache.json` 的来源和次数；旧 `tmp/zipline_motion_cache.json`
   保持原样。清除新缓存前先停止任务并备份文件；保留旧文件时重启应用会重新导入弱 legacy 记录。

### 淤积点战前入口

`BattleTask.battle_gather()` 使用本次传送返回的临时 `GatherEntry`。只有传送按钮确实点击成功、
`ensure_main()` 已确认稳定主界面，并且新帧画面稳定后才授予入口资格；没有要求先识别淤积点
HUD。失败、未知关卡或入口不稳定时继续原视觉流程。入口还绑定关卡、捕获尺寸、滚轮策略及
learning epoch，切换关卡、战斗或尺寸变化后不能使用旧 token。

无滑索时，`after_transfer` 会话包围原来的第一次横向对中。“索引 → 选定淤积点 → 快速传送
完成 → 落地主界面稳定”本身就是稳定入口，以关卡保存私有经验；可靠样本足够且低方差时按
high 完整重放，不额外要求识别传送点名称或先识别目标。可靠 yaw 仍单独参与匹配，读不到时
使用独立的未知 yaw 身份，不编造角度，也不因此固定减半。不在地面为了借经验主动归一化
朝向。上下文 key 保持不变，已有重放加微调的累计动作样本继续有效；未知物理 family 不猜共享。

有滑索时，`after_zipline` 会话位于末端仍在架上的第一次 HUD 对中，entry 明确为
`after_zipline_on_board`，完整入站路线参与身份。保留原有 `need_v=False`，不额外加 V 或
重新登架；也不借用送货 reboard 姿态。段级路线用 canonical 关卡名作为私有配置键，不猜共享
family。首次 HUD 对中保存后关闭会话，再下架；后续 `battle_gather()` 补正和导航不重复学习。

淤积点复测可选择有滑索和无滑索的关卡各重复执行，观察
`[gather-learning] ... entry=after_transfer confirmed=True`，随后
`[initial-align-learning] verified target=gather:<关卡> saved=True`。同入口干净样本足够后，
会先出现 replay，再由新帧验证。搜索/部分输入不保存；后续导航异常不改已提交样本。
战后原地找领奖点、仅通过 F8 重新追踪而没有实际传送，继续保留外层 deny。

### F8 重新传送后的相同入口

`_gather_retry_navigate()` 与战前导航共用 `_transfer_to_gather_stage()` 和
`_prepare_gather_navigation()`：选定同一关卡、完成快速传送并确认世界画面稳定后，
建立同一套滑索路线／架上目标对中，或无滑索落地点对中。业务指纹不增加“战后”字段，
因此相同关卡、路线、捕获配置与朝向可复用战前已有的可靠经验，无需重新积累独立样本。
两条路径的差别仅是初始化后的目标提示：战前检查挑战，恢复链检查领取／放弃奖励。

`gather_retransfer_learning()` 在实际传送及稳定帧证明成立后，临时替换 post-battle 禁止状态，
允许上述初始化中的经验读取、重放与新帧自验证保存。此窗口前后的 epoch 都更新，旧入口
或漏出的会话不能复用；异常和停止始终恢复父级禁止。传送失败、未知关卡、画面不稳定、
证明期间关卡／尺寸／滚轮／epoch 变化均不开放窗口。活动战斗或其它禁止原因也不能被覆盖。

首次对中保存后即结束该会话，不等到达或领奖；窗口在 `navigate_until_target()` 前关闭。
后续步行、搜索、交互及领奖保持不学习，失败不撤销初始化样本。滑索链的每段初始对中及
末端架上首次对中仍各用原有作用域，途中补正不另外学习。

淤积点当前验证为离线实际调用链测试；HUD 几何参数、入口稳定性及收益仍需游戏现场验证。

### 重复导航测试任务

“工具与调试 → 淤积点重复导航测试”独立保存参数，可在“淤积点序列”中按任意顺序添加关卡，
允许重复同一关卡。“循环次数”默认 5，表示完整执行序列 5 遍；设为 0 时持续运行到手动停止。
例如序列“武陵城、首墩、武陵城”配合 2 次循环，会执行 6 次导航。滑索路线沿用全局配置。

每次都经 F8 索引重新选择关卡，复用 `BattleTask.navigate_to_gather()` 的正式传送、滑索、
初始学习与导航，仅观察稳定的“挑战”提示确认到达。任务不进入激发、挑战、换队、领奖或战斗
流程，也不消耗体力药。失败会记录 `[gather-nav-test]` 并继续后续关卡，结束时汇总成功与失败。
每次导航退出均释放方向键，手动停止正常向外传播；重启插件执行器后可发现新任务。

### 卖货、联络与演算入口

`workflow_learning.py` 为这三种流程提供一次性运行时入口证明。证明绑定任务实例、
learning epoch、目标及捕获尺寸，不写入缓存；消耗后不能拿它在另一个位置再次初始化。
历史动作仍持久保存，以后重新建立同一入口时可继续复用。目标暂时识别不到不阻止重放，
但只有输入后的真实新帧对中才保存；nav、终端交互、聊天或进入演算都不作为保存条件。

- **卖货**：`buy_sell()` 真正点击“前往”并确认到达好友船，画面稳定后才授予新落点入口。
  上下文按“前往好友帝江号 → 稳定落点 → 物资调度终端”及捕获 profile 匹配，
  不因所选好友名称或售卖货品地区不同而拆散相同入口的经验。干净可靠样本足够时
  high 完整重放；入口不稳定则只走原视觉流程。已经在好友船任意位置直接调用
  `navigate_to_friend_exchange()` 不获得落点资格。
- **联络**：只有本次默认舰桥传送、实际前进并识别到中央环厅才建立入口。一次和两次
  一秒前进分别存储；共享“已在帝江号”状态、自定义传送点、未确认环厅都不证明同一起点。
  定时行走不能保证完全相同的停止位置，因此此入口 medium 半量重放后由视觉校正；
  初次对中后便消耗证明，途中遇人聊天再导航不重复使用落点经验。角色名字 OCR 不接学习。
- **演算**：总览选定演算目的地、快速传送成功并落地稳定后，在 `demographic_follow`
  第一次 xy 对中接入 high 私有完整重放。传送失败或 epoch 改变不授予入口，后续
  `navigate_until_target()` 和 `enter_page()` 不携带学习会话。
