# 07 · BASELINE_DATA — 静态角色伤害基准数据库（第一阶段）

> 口径确认日期：2026-09-24。本文件定义第一阶段「静态角色伤害基准」的数据口径、
> 证据链与缺口。第二阶段（敌人抗性/Buff/队伍联动/时间轴/DPS/Rotation）另起。

## 1. 口径

**固定条件**（全角色统一）：

| 项 | 值 | 来源 |
|---|---|---|
| 角色等级 | 90 | `character_skills/*.json` → `base_stats`（官方属性面板） |
| 技能等级 | 专精3（rank_stats 末列） | `rank_stats`（官方 WIKI 数值表） |
| 武器 | 90 级，官方游戏内推荐 | 森空岛 WIKI 干员页「武器推荐」（游戏内推荐源） |
| 武器技能 | Rank 9（= 基础等级 + 推荐基质满蚀刻） | 武器页 Rank 表 |
| 武器基质 | 官方武器页「推荐武器基质」 | 同上；基质词条=武器技能等级提升 |
| 装备 | 4 件 = 护甲+护手+配件×2，LV70 金色，精锻3 | 装备页「基础属性/装备精锻」表 |
| 套组 | 主套组 3 件 + 散件 1 件 | 社区攻略（证据链见 §3） |
| 假人 | DEF=0、RES=0、无失衡、无连击、无队友、无 DoT 状态 | 防御倍率=抗性倍率=1 |

**计算公式**（`compute_damage_baseline.py`，标准假人下的简化）：

```
攻击力   = ((干员攻击 + 武器攻击) × (1 + 攻击%) + 攻击固定)
           × (1 + 0.005 × 主属性 + 0.002 × 副属性)
非暴击伤害 = 攻击力 × 总倍率 × (1 + Σ伤害加成)
           Σ伤害加成 = 元素伤害% + 技能类型伤害% + 所有技能伤害% + 所有类型伤害%
暴击期望  = 非暴击伤害 × (1 + 暴击率 × 暴击伤害)    基础 5% / 50%
```

- 主属性优先取官方干员标签「主能力」（力量/敏捷/智识，10207 组 tag）；
  缺少官方标签时按元素推断：物理→力量，其余→智识，trace 标明来源。
  副属性仅取官方干员页属性表「副能力」标注（金色=主、黑色=副，
  可为意志）；缺失时不计副属性系数项。
- A 层裸伤害只统计**无条件**词条：武器技能/套组效果文本中含触发词
  （当/后/时/使/如果/若/释放/击败/低于/高于…）的句子不计入。
- 技能总倍率 = `rank_stats` 中标签含「倍率/伤害/攻击」行的末列求和；
  「处决」「终结技期间」等条件变体行单列不计入（C 层再算）；
  「失衡值」行汇总为削韧参考。
- 普攻倍率为连段合计（含下落/重击段），处决倍率单列。

## 2. 数据链路（全部可重跑）

```
capture_skland_item_details.py      # 抓武器(80)/装备(258)/基质(60) item/info
  → tools/wiki_catalog/item_details/<stamp>/
build_loadout_data.py               # 解析 → assets/data/{weapons,equipments,matrices}.json
generate_character_builds.py        # 干员页武器推荐 + 武器页反向互证 + 社区套组
  → assets/data/character_builds/<key>.json
compute_damage_baseline.py          # 面板 + 逐技能伤害 + 完整计算过程(trace)
  → assets/data/damage_baseline.json
```

装备套组归属/部位/品质/主能力来自官方 tagIds + filterTagTree 解码，
非名字前缀推断（「长息护手」属潮涌组、「长息护手·壹型」属长息组的坑已规避）。

## 3. 配装证据链

| 等级 | 来源 | 覆盖 |
|---|---|---|
| 1（官方） | 武器与基质：森空岛 WIKI 游戏内推荐，干员页⇄武器页双向互证；装备：WIKI 装备页「推荐干员」卡片反查（`equipments.json.recommended_operator_ids`） | 32/32 武器、31/32 基质、25/32 装备 |
| 2（社区攻略） | 新浪「全干员装备适配一图流」（毕业 3+1）；ldcapple 精确四件套 | 4 角色（官方装备链未覆盖处回退） |
| 3（启发式） | 按元素套用同源社区模板（物理→点剑3+碾骨1 等），**待专属攻略验证** | 其余角色 |

装备官方链只推荐 3 件时，pieces 按官方原样收录（3 件同套即触发套组效果），
第 4 件官方未指定（build `equipment.note` 注明「自由散件」）；官方推荐不足
3 件同套组时 `set_main` 记 null（无套组效果，忠实官方原样）。

注意：英文站 gamestratport 的「点剑 3pc=物理伤害+15%」与官方 WIKI 套组效果文本
（点剑 3pc=失衡效率加成+20%）冲突，**以官方文本为准**；引用社区数值前先对照
`equipments.json` 的 `set_effect` 字段。

## 4. 已知偏差与边界

- `管理员`（endmin）的男/女官方条目统一映射到角色名，武器推荐与主/副能力按官方数据计入。
- 赛希战技为治疗/增幅技能（无伤害倍率），伤害记 0 属正常。
- 庄方宜战技为召唤物多段机制：单击倍率 45% 只是雷击单发，完整战技 =
  3 柄青霆剑依次雷击 + 最后一击 6 倍（45% x (2+6) = 360%，按 wiki 专精 3
  技能表、满导电常态 3 柄上限建模）→ 已入 `_SKILL_FULL_MULTIPLIER_OVERRIDES`
  覆盖表（`full_expect` 字段），导电等级加成（9%/级）等条件词条不计入。
- 提弗洛斯为浮空多段机制（wiki 快照 2116，2026-09-25 复核）：战技「风矢穿林」
  浮空可施放 5 次空中普攻（第 5 次 = 空中重击 + 强化射击，无需猎矢）
  → 345% 覆盖为 540%（起跳 50 + 空中普攻 65 x 4 + 重击 100 + 爆发 130，
  单目标、无猎矢强化保守建模）；终结技「冰山呼告」箭雨 5 轮（第 5 轮强化）
  → 575% 覆盖为 800%（爆炸 300 + 常规箭雨 75 x 4 + 强化箭雨 200）。
  猎矢转化、附着消耗的爆发提升属条件词条不计入。
- 「诀」的阵诀·智/意多形态只取主形态 rank_stats（变体在 `rank_stats_variants`）。
- 武器潜能（满潜能）数值官方页面为图片，未数据化（见 §5）。
- 条件型套组效果按基准口径不计入裸伤害（壤流「消耗导电→电磁+15%/层」、
  动火用「燃烧/腐蚀→增伤」、脉冲式「导电/冻结→电磁/寒冷增伤」），但对触发
  频率高的角色（庄方宜、莱万汀、佩丽卡等）是接近常驻的实战收益——裸基准
  会**结构性低估**这些流派的输出，排行仅供参考。
- 插板/护板类装备的「主能力 +X%」词条已解析（`pct_primary`），仅乘主能力
  总值，副能力不吃。

  处决伤害 = 常规伤害 × 处决承伤系数（敌人阶层 1.0/1.25/1.5/1.75），乘算；

- **P1** 基质随机词条的附加属性选择（每角色最优 2 条）→ 目前只记官方推荐基质名。
- **P1** 技能 B 层（技能自身施加的状态吃自身伤害，如噗切娜终结技法术脆弱 2.5%）。

- **P2** 装备散件第 4 件的角色级最优选择（现在按套组自动选件，未逐角色论证）。

## 6. 用法

```bash
# 全角色重算
python scripts/skill-data/compute_damage_baseline.py
# 单角色 dry-run：打印 trace 和排行，不写入共享基准；写入需显式传 --out
python scripts/skill-data/compute_damage_baseline.py --char puqiena
```

运行时消费：`src/data/skill_rotation.py` **只读 `assets/data/damage_baseline.json`**
（不直接读技能 JSON）——按顶层 `cycle_expect`（**循环期望** = 战技完整伤害
含召唤物/多段 + 连携 + 2x 普攻，对应自动轴 12.5s 填充段的站场普攻）降序
生成两种产物；旧数据无 `cycle_expect` 时回退单发战技暴击期望。战斗配置
「自动技能列表」+「伤害优先排序」开启时由 `AutoCombatLogic` 使用，
基准数据缺失的角色排最后。
⚠️ 因此修改 `character_skills/*.json` 后必须重跑 `compute_damage_baseline.py`
重算基准，才会影响排轴排序。
⚠️ 循环期望是**启发式排序口径**（非帧级 DPS）：社区排轴/模拟站点
（endfield.metriclabs.net 全自动伤害模拟器、end-axis.com 排轴器、
perlica.tech Perlica Calc）做帧级 buff/状态追踪，精度更高；本基准的优势是
随官方数据自动重算、零维护。

- `generate_damage_rotation`：战技槽位列表（"1"-"4"），普通模式循环释放；
- `generate_auto_rotation`：**自动排轴**——覆盖队内全部 1-4 号位的可重复循环轴：

  ```
  [战技N] [ult_N]（每号位一段，伤害降序） + [e]（第 1、3 段后） + [normal_12.5]（每段后）
  ```

  4 人队一轮 = 4 战技 + 4 终结技 + 2 连携窗口 + 4 普攻回能填充段。
  SP 配平：全队技力共享、战技 100/个、恢复 ≈8/秒（12.5s/100 社区值），
  每段填充 ≈ 恢复一个战技的技力，整轮收支平衡；周期 ≈50-56s，
  大于终结技 CD（20s 量级）， ult 每轮必转好，未就绪由执行端跳过推进、
  下轮再试（不卡轴）。填充段保持普通战斗（普攻回技力 + 推荐技能/终结技兜底），
  不发数字战技（技力留给轴）。

- **冷启动分流**（协议空间自动识别）：`AutoCombatLogic` 在排轴生成前检测
  `battle_space_left` 特征（战斗画面左上角「撤离」按钮，协议空间常驻、
  普通战斗没有；初始等待窗口与战斗中识别尝试时顺带检测，命中一次即定）：
  - 检测到（协议空间，开局终结技全满）→ 轴含 `ult_N`，按伤害序倾泻；
  - 未检测到（普通战斗，能量从零攒，"冷启动"）→ 轴不含 `ult_N`
    （`generate_auto_rotation(include_ult=False)`），避免前几轮循环空转；
    终结技就绪后由填充段的 `use_ult()` 兜底通道自动释放，不会漏放。
  误判两侧都有兜底（冷启动漏排的 ult 走兜底；热启动排了的 ult 未就绪
  会被跳过），不会卡轴。已知限制：`battle_space_left` 仅标定 1080p
  （无 `_2k`/`_4k` 变体），更高分辨率下的可靠性待实测。

- **脉冲探针**（独立诊断，默认开）：`src/image/pulse_probe.py` +
  `battle_mixin.probe_pulse()`，挂在 `AutoCombatLogic.run` 主循环每帧
  （所有走 `auto_battle` 的战斗——主线/日常/演示/影拓——全覆盖，
  与战斗模式/配置组合无关）。复用白色圆周检测算法（独立去抖实例 +
  0.25s 节流 + 全屏闪光过滤），**只记录不按键**：上升沿追加写入
  `configs/pulse_probe_log.jsonl`，字段含时间、批次区域（批次1-4）、
  按键编号、角色映射（`_battle_team` 尽力而为，缺队伍信息时记 null
  并监测全部 4 区域）、白色占比、人数、任务名。用途：实战统计
  「哪些强化态/技能有官方推荐脉冲」，为把推荐时机反哺排轴提供数据
  （如增强态角色在轴上等脉冲再放）。覆盖范围限制：任务若有自己的
  独立战斗循环（不走 `auto_battle`），探针不生效。
