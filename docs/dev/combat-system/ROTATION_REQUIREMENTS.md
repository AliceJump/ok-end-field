## 4. 对自动编排器设计的约束（已可实现的版本）

P0-2 的处决倍率组合规则已采信实测结论；P0-3 的敌人面板数值尚未确认。以下编排规则已可落地：

1. **资源轴优先**：SP<100 时排普攻（回技力+叠失衡），SP≥100 插战技；战技→命中→充能→能量满放大招，循环天然成立。
2. **连击规划**：连击层数≥1 时战技/终结技必吃加成——先低倍率战技叠层、高倍率终结技收尾。
3. **反应队列**：法术队维护 `inflictions{element: stacks}`，模拟「A 叠 4 层 → B 触发」；物理队维护破防层 → 猛击/碎甲消费点。
4. **失衡窗口**：`StaggerBreak` 事件后 X 秒内倾泻终结技+高倍率战技（×1.3+对失衡词条），首个普攻槽留给处决。
5. **连携即时释放**：连携免费且有 5s 窗口，就绪即排入（注意大潘/骏卫类条件连携与破防层消费的顺序耦合）。
6. **执行端对接**：编排输出 = 本仓库排轴 token 序列，由 `AutoCombatLogic` 循环执行；连携用 `e`、终结技 `ult_N`、战技 `1-4`。
7. **喂养顺序**（已实现）：满口径依赖元素附着的角色（提弗洛斯需自然附着
   供给启示），排在其喂养者之后——`generate_damage_rotation` /
   `generate_auto_rotation` 的 `_ordered_slots_with_dependencies`：
   贪心「约束已满足者优先」，伤害降序为权重；依赖不满足时该角色排序
   口径自动回退保守值（见 BASELINE_DATA），此时无顺序约束。显式传
   baseline 的调用方无依赖信息，退化为纯伤害降序。

## 5. 建议的验证路线（低成本→高成本）

1. 用本地 rank_stats 已知失衡值打木桩/低级怪，反推失衡槽上限表（P0-3 部分）。
2. 固定配装打同一怪物，对比 失衡/非失衡、暴击/非暴击 截图伤害 → 校准 1.3 与 P0-5，并对照已采信的 P0-2 处决组合规则。
3. 录屏逐帧标定 3 个代表性技能（普攻末段/战技/终结技）的前摇-命中-后摇（P0-1 起步集）。
4. 参考 Dim-Halo/Endfield_Simulation（0.1s tick）与 wxhwwla/calc-framework（15 乘区）的开源实现校准。
