# 机制排轴模型后续计划（2026-10-07）

分支：`codex/effect-semantics-normalization`。本计划接续 [机制模拟续接检查点](mechanism-continuation-checkpoint.md) 与 [原生动作执行进度](native-combat-execution-audit.md)，目标是让机制模型真正参与实战排轴，而不是继续按节点逐个补齐原生虚拟机。

最新推进顺序以[实际阻塞诊断与计划](mechanism-blocker-plan.md)为准：诊断依赖 → 四人队动作闭环 → 连续观测 → 收益/预算 → 全角色与现场验收。下文两层模型仍是方向，阶段号不再代表应先完成全部节点后才接入识别端。

## 2. 总体方向

采用两层模型：

- **离线真值层**：保留现有原生模拟器，继续严格执行“未知即拒绝”，用于生成与校验数据，不进入实战热路径。
- **在线抽象层**：由真值层导出每个动作的宏模型（SP 消耗/返还、能量、伤害期望或上下界、状态产生/消费、时序窗口），状态小且可哈希，供实战搜索使用。

完整性从“全部节点已绑定”改为“所有可能影响目标量的节点已绑定”。

[机制模拟续接检查点](mechanism-continuation-checkpoint.md) 第“下次从这里继续”列出的 6 项按以下方式处理：

| 原计划 | 处置 | 原因 |
| --- | --- | --- |
| 1. 属性 57/58 默认值 | 暂停，并入阶段 5 | 只影响导电、冻结的部分伤害，不在阻塞榜前列 |
| 2. 冻结子 buff 与碎冰 | 暂停，并入阶段 5 的子 buff 寿命 | 子 buff 寿命统一处理，收益更大 |
| 3. 腐蚀、燃烧细节 | 暂停，并入阶段 5 | 同上 |
| 4. 异常起止回调、附着增强 | 暂停，并入阶段 5 | 约影响 15 个程序，按决策影响排序 |
| 5. 其他伤害处理器 | 暂停，并入阶段 5 | 同上 |
| 6. 消除真实队伍未解析机制 | 继续，按最新诊断计划A–C推进 | 启动、动作执行和观测都需闭合，不能仅优化性能或改变判定口径 |

前置任务：先完成 [固定配装补全规划](equipment-allocation-plan.md) 并重算固定面板，再进入阶段 0。面板是所有伤害计价的输入，配装不完整会让后续对比失真。

## 4. 阶段计划

### 阶段 0：基线工具化

- 把本次统计做成仓库脚本 `scripts/skill-data/audit_mechanism_coverage.py`，输出可计价程序数、阻塞类型频次、每角色明细，以及 fork/simulate/搜索耗时。
- 结果写入 JSON，后续阶段的 PR 描述引用前后对比。

验收：脚本复现完整程序树与启动诊断数字；不改变任何运行时行为。已完成基础审计；开场可达性、动态缺口和推荐门槛还需一起报告。

### 阶段 1：性能底座

- 不可变对象（`ActionProgram`、`CombatEvent`、`Native*` 冻结 dataclass）在 `fork` 时共享引用。先逐个确认这些类不含可变字段，含可变字段的改为元组或冻结映射。
- `_execute_event_body` 的输入构建改为按需求值：只计算该事件表达式实际引用的 `count.*`、`native.*`、属性键，不再每个事件遍历全部 `EffectType`。
- 搜索去重键改为增量维护的哈希，避免每次展开 `repr` 整个 buff 定义与队列。

验收：四人队 `fork` < 1 ms，单程序 `simulate` < 2 ms，完整可计价负载验证深度2、144次展开上限和25ms预算；全仓测试通过，模拟结果与优化前逐项一致（增加对拍测试）。fork已达标，后两项不能用未知提前失败或非法替换动作计时验收。

### 阶段 2：按目标相关性判定完整性

- 节点处理从 if/elif 链改为按原生类型名注册的处理器表，每个处理器声明读写集合：伤害、SP、能量、buff 状态、冷却、技能槽、时序、控制流。
- 新增“场景忽略”分类：在声明场景（单个静止敌人在命中范围内、时序取实测时间线）下，写集合与目标量无交集的节点显式忽略，并记录场景假设与依据；不再计入 `unresolved`。
- 首批候选：霸体、时间膨胀、忽略全局时间缩放、镜头相关检查、距离保存、曲线求值（仅当输出只流向位移/表现）、牵引/击飞/倒地的位移部分、目标空间过滤（单敌人场景）。
- 打断、跳转、`ComboCache`、`TemporaryUnlock` 影响控制流或可用窗口，不能直接忽略；逐个确认其对实测时间线是否已经覆盖，覆盖则绑定为时序约束，未覆盖则保留未解析。

验收：每个排除项都有完整消费者与控制依赖证明及回归，场景假设出现在日志与诊断里；同时报告真实队伍启动/可达动作/严格执行门槛。取消未复现的9/111估计作为阶段硬指标，完整树2/111仍独立保留。

### 阶段 3：区间计价

- 仅对已有可证明边界的未解析部分给出伤害与资源区间。旧排轴报价不是上界；未知目标数、触发次数或后续状态没有证据时，不能拿文字倍率或任意0下界凑成有效区间。
- 推荐规则：某候选下界大于其余候选上界时才由机制模型决定，否则回退旧排轴；日志记录区间与回退原因。
- 控制流未知（可能改变后续动作合法性）的节点仍整条拒绝，不进入区间计价。

验收：至少一支真实队伍（如弭弗/骏卫/余烬）在部分时段由机制模型给出推荐；新增测试覆盖区间重叠时回退、区间分离时接管。

### 阶段 4：在线抽象模型与离线策略

- 从真值层为每个动作导出宏模型，校验抽象模型与真值层在合成序列上的伤害、SP、状态一致（允许已声明的误差）。
- 末端估值：用离线稳态循环计算 SP、能量、就绪状态的边际价值，消除 6 秒/2 步窗口的短视。
- 固定队伍可离线预计算“状态 → 动作”策略表，实战查表，搜索仅作为表外兜底。

验收：在线决策 < 5 ms；离线评估中，机制策略的循环伤害不低于旧排轴，且对生产者动作（返 SP、解锁消费）的选择与真值层长窗口搜索一致。

### 阶段 5：按决策影响补长尾

- 用阶段 0 脚本统计每类剩余阻塞对“推荐是否改变”的影响，按影响排序补绑定。
- 预计优先级：子 buff/动作绑定寿命 → 投射物 → 能力实体 → 异常起止回调与引燃时间线 → 其余。
- 属性 57/58 默认值、碎冰与腐蚀细节等仅在影响排序时提前。

验收：每补一类，报告可计价程序数和受影响队伍数的变化。

### 阶段 6：实战校准

- 录屏或日志采集 SP 曲线、技能确认时刻、伤害数字（可得时），与模型预测对比，统计漂移。
- 漂移超过阈值时自动降级到旧排轴，并记录原因。

验收：至少两支队伍完成现场对比记录；模型接管时段内无因预测错误导致的施放失败率上升。
