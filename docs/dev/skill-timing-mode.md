# 本地技能时间排轴实验

本模式基于伤害排轴功能，使用仓库内预生成的全角色技能时间数据，并增加独立的「技能时间排轴」开关。默认关闭。

## 使用方式

在战斗配置中打开「技能时间排轴」。任务启用「使用独立配置」时读取该任务的战斗配置，否则读取全局战斗配置。开关开启后，入口直接进入 `TimedCombatLogic`，优先于手写排轴、实时条件、推荐技能、自动技能列表、伤害排序开关、立即释放和启动技力点数等旧策略；关闭后继续执行原模式。旧配置的值保留。任务是否开启、调用方的 `no_battle`/`deadline` 和终结技按键方式仍按现有任务约定处理。

新模式复用 `battle_mixin` 的稳定队伍识别、技力条识别、连携就绪检测、终结技检测及释放、战斗结束确认。连携检测提取为 `is_link_skill_ready()`，普通模式和新模式共用。在后续实验分支 `codex/timing-dps-rotation` 中，战技采用 [可重复循环 DPS 搜索](timing-dps-rotation.md)，数据不足时使用原伤害排序。技力不足时继续普攻等待；资源到位后继续，不插入固定 `normal_12.5` 填充段。时间轴只约束战技/终结技/连携之间的衔接。战斗期间左键普攻持续按住，并每 0.25 秒重新发送一次按下作为恢复心跳，避免技能动画、窗口焦点变化或游戏输入状态重置后本地仍误以为左键保持；退出确认、no_battle 和最终清理时才松开。 当技力 HUD 显示 3 格已满时，当前规划序列的下一个战技在前一个角色达到 effect handoff 后会抢占连携与终结技，优先消耗技力防止长期饥饿和溢出；同一角色自身仍保留保守接续限制，不会因为 allow-next 存在就主动打断持续姿态。

## 数据接口与范围

`assets/data/skill_timings/20261002/` 包含：

| 文件 | 内容 |
| --- | --- |
| `index.json` | 753 个角色技能的轻量索引、原生角色 ID 与仓库角色名称映射、等级补丁、来源摘要和验证结果 |
| `records.json.gz` | 754 个 SkillData、594 个 BuffData，共 1,348 个完整记录；保留条件分支、原始曲线、空串/null 等细节 |
| `raw.zip` | 同一批 1,348 份原始二进制文件 |
| `native_read_plans.json.gz` | 原生读取计划，用于独立重新编码复验 |

数据覆盖 33 个标准角色 ID（男/女管理员分开），另保留实际文件前缀 `chr_032_lizhiyan`，不猜测合并；CharacterTable 中虚拟 `chr_9000_endmin` 没有独立技能记录。各技能是原生名称，不能与 WIKI 命名直接拼接：原生 `normal_skill` 表示战技，仓库 WIKI 的 `*_normal` 表示普通攻击。

`load_skill_timings().profiles(character, kind)` 接受仓库中文名、规范化英文 key、英文名或原生 ID；`kind` 为 `battle`、`link`、`ult`。管理员头像不能区分性别时返回两份候选，执行器要求两者都满足接续条件。完整记录通过 `record(skill_id)` 延迟加载，并检查 SHA256，不进入战斗每帧循环。

## 第一版时间规则与局限

- 原生帧字段按 **名义 30 帧/秒**换算。它们是作者时间轴，尚未通过游戏中的动画、时停和攻速变化校准，不能声称是实际前后摇。
- `exclusiveFrame` 不再作为全队硬锁。完整 `records.json.gz` 中的顶层、无主控/协同条件依赖 gameplay action 用于派生 `effect_start`：直接伤害、法术附着、弹道发射、AbilityEntity、Aura，以及可识别的非 UI/VFX gameplay Buff。条件分支内部事件不用于抢早；无法可靠派生时继续使用旧的 `actionable` 保守兜底。
- 不同槽位角色在当前技能达到 `handoff = max(0.3s, effect_start + 0.05s)` 后可以继续排轴；同一槽位角色仍使用明确匹配的 `AllowNextSkillAction` 或旧 `exclusive/actionable` 兜底。`AllowNextSkillAction` 只是“允许这样衔接”，不会触发自动中止持续姿态。
- 连携监测不能识别释放者，因此连携释放后的跨角色 handoff 使用队伍所有可能连携 profile 中最慢的 `effect_start`；任何成员缺少通用连携映射时仍不自动发送连携键。
- 终结技不使用 `exclusiveFrame` 作为全局动画锁。执行器复用现有“队伍头像消失为 `?` → 完整队伍重新出现”的 HUD 同步；HUD 恢复后立即清除全局终结技锁，持续 Buff/姿态继续自然运行。
- 角色等级未识别时，费用和 CD 使用等级补丁的保守上限；一整格技力按 100 SP 换算。战技输入后以技力条下降确认消耗，未确认时保留原槽位并等完整窗口结束再试。免费战技只有按键尝试证据，按时间轴和 CD 限频，不宣称已经命中。
- 弭弗 `normalskill_1/2/3`、提弗洛斯 `normal_skill_floating_start/loop/end`、洛茜 `combo_1/2/3_skill` 的完整数据均在快照中，尚无可靠的运行状态选择映射。暂不自动发送弭弗/提弗洛斯战技，其他队友仍可出技；队伍含洛茜时不自动释放连携。识别不到完整四人队伍时只普攻并继续尝试识别。
- 长持续技能不再因为完整 `duration` 自动形成同长度保护窗口；真正的硬等待由 `exclusiveFrame` 决定，并在其后留 0.15 秒边界余量。该策略更激进，是否存在个别技能仍需等待更久必须靠实战日志校准。时间排轴使用 Alt 释放终结技时跳过头像“全未知→恢复”的同步等待，依赖技能时间保护与现有 3 秒退出判定保护继续监测；长按终结技仍保留旧同步流程。

## 运行时验证

技能时间数据作为预生成资源直接随仓库读取；运行时不包含生成或提取链路。相关回归测试可直接运行：

```powershell
uv run --locked python -X utf8 -m unittest tests.TestSkillTiming -v
```

时间字段用于调度提示，不等同于实战命中证明；仍需结合实战日志继续校准。
