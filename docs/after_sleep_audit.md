# after_sleep 审计与优化

## 范围

基线为 `optimize/waiting-log-followup` 的 `03b23ee`。审计覆盖 `src/` 下全部 Python
任务，以及 `logs/` 中 2026-06-13 至 2026-07-28 的运行记录。

- `after_sleep` 定义、透传和调用共 181 处。
- 基线显式非零 `after_sleep` 调用共 144 处。
- 本轮优化后显式非零调用剩余 42 处。（最终定稿数见 `optimization_validation_handoff.md`：41 处）

统计不等于全部删除：公共 API 的默认零值和参数透传仍然保留。

## 分类原则

### A 类：后续状态已经可检测

点击后紧接 `wait_ocr`、`wait_feature`、`wait_until`、`wait_ui_stable` 或
`ensure_main`。固定等待移除，由目标状态 timeout 接管；成功时立即继续。

本轮处理范围：

- 公共确认框、登录和切号。
- 地图打开、筛选、追踪、传送点和传送按钮。
- 战斗入口、领奖、重开、奖励档位和演算页面。
- 活动奖励、日常奖励、邮件、转交委托奖励。
- 买物资、买卖货、信用商店、据点兑换、基地收菜。
- 运送接单、提交、任务页返回、仓库切换和一键存放。
- 影拓丰碑和演算抽牌。

### B 类：需要短动画窗或局部稳定

- 战斗领奖点中键回正由 2 秒降至 0.3 秒，随后立即 Yolo/OCR 检测。
- 地图筛选和商品分类改用 `wait_ui_stable`，不使用固定时长。
- 运送接单等待“接取按钮消失”并要求稳定 0.3 秒，最长 3 秒。
- 仓库页面等待地点 OCR，确认按钮改为最长 1 秒轮询。

### C 类：保留

- 滑索右键、上索、视角重置等物理交互顺序。
- `click_with_alt` 的 Alt 按下前置间隔。
- 战斗闪避、技能排轴和用户配置的 `sleep_N`。
- 批量药剂、礼物数量点击等缺少可靠视觉计数的输入节流。
- 自动拾取、触发任务和实时检测的轮询降频。
- 商店/委托刷新服务端 CD。
- 滚动动画和鼠标修饰键按下/释放间隔。

## 主要修改

### 确认与登录

`click_confirm` 默认不再固定等待，新增 `disappear_time_out` 作为确认按钮消失的最大
等待时间；原 `after_sleep` 参数仍保留固定延迟语义，避免破坏调用契约。现有业务调用
已改用按钮消失检测。登录流程删除等待函数之外重复的 1 至 2 秒，并直接等待登出按钮
和确认按钮。

### 地图与导航

按 `J` 后等待 `one_task_to_map`，点击地图定位后等待 UI 稳定；点击传送点后由
`transfer_go` 检测接管。追踪后按 `M` 不再先睡 3 秒，直接轮询场外追踪图标。

### 战斗与奖励

战斗入口、重新挑战、领奖按钮之后均已有下一状态检测，删除 1 至 2 秒后置等待。
普通奖励点搜索中键等待保留 0.3 秒。最新日志中四轮 Yolo miss 原本每轮包含 2 秒
等待，理论可再减少约 6.8 秒。

### 运送与仓库

接单从“点击后睡 2 秒，再检测”改成最长 3 秒轮询按钮消失；命中即可提前返回。
“请尽快送达”的点击前稳定要求由 4 秒降至 0.5 秒。仓库切换、确认和已连接状态
均由 OCR timeout 接管。

## 预估收益

- 地图传送链：每次约减少 4 至 8 秒固定等待。
- 普通战斗奖励搜索：四次 miss 样本约减少 6.8 秒，九次全 miss 最多约 15 秒。
- 运送正常循环：按历史路径约减少 10 至 20 秒。
- 登录切号：约减少 4 至 7 秒固定等待，不改变 120 秒登录上限。
- 演算三轮：约减少 5 至 8 秒。
- 邮件、基地、奖励和商店收益取决于当日可领取项数量。

以上是按历史固定等待命中估算，不能替代实机日志对比。

## 未处理风险

加载画面仍可能触发重复 ESC。当前资源中没有可靠 `NOW LOADING`/`TIPS` 特征，
因此本轮没有用 OCR 猜测加载状态。应先采集不同分辨率和语言的加载截图，再增加
明确特征；不能通过扩大或缩小固定 sleep 规避。
